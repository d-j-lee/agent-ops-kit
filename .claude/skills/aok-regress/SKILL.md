# aok-regress — 회귀 고정 런북

규범: `docs/patterns/regression.md`. 이 스킬은 그 절차를 실행 순서로 줄인 것이다.

## 1. 먼저 정할 것

| 질문 | 답에 따라 |
|---|---|
| 기준이 무엇인가 | 기준 커밋 sha(또는 기준 구현 경로)를 적는다. 기준이 없으면(빈 저장소, 얕은 클론) 통과가 아니라 비교 불가로 멈춘다 |
| 무엇을 비교하나(투영) | 종료 코드와 stdout이 기본이다. stderr에 의미가 있으면 `--stderr`. 출력 일부만 보면 그 범위를 한 줄로 적는다. 보고서의 "같다"는 이 범위까지만이다 |
| 비결정 요소가 있나 | 시각, 난수, 세션·캐시 상태, 경로·시간 표기. 옵션으로 고정하거나 `--normalize`로 지우고 몇 번 지웠는지 보고한다 |
| 양쪽이 상태를 공유하나 | 빌드 디렉터리, 캐시, 출력 경로를 쪽마다 따로 둔다 |

## 2. 실행 순서

1. **기준 고정.** 시각·시드를 옵션으로 고정한다. 상태를 기억하는 도구(세션별 기록, 캐시)에는 실행마다 새 키를 준다. `diffcheck.py`는 명령 인자와 `--stdin` 파일 안의 `{nonce}`를 실행마다 새 토큰으로 바꾼다. 키 자체로 갈래가 나뉘는 도구(키 해시로 보류군을 고르는 등)면 `--same-nonce`.
2. **FAIL_TO_PASS.** 버그 수정이면 실패하는 테스트를 먼저 만들고 실패 출력을 보존한다. 고친 뒤 통과를 본다.
3. **PASS_TO_PASS.** 전체 테스트를 돌린다. 선택 의존성·기능 플래그가 갈리면 갈래마다.
4. **음성 대조: 공허함 검사.**
   ```
   python3 -I scripts/vacuity_check.py --repo "$REPO" --test "$TEST_CMD" --mutations muts.json --jobs 4 --json
   ```
   - 변이 하나는 "보호 장치 하나를 끄는 최소 변경"이다(조건 삭제, 경계 바꾸기, 호출 생략). 대상 코드에 넣고 테스트 파일은 건드리지 않는다. 문법이 유효해야 한다.
   - 항목 형식: `{"file", "old", "new", "label", "expect"}`. `expect`에는 그 변이를 잡아야 할 테스트 이름을 적는다.
   - 판정: `guarded`만 통과다. `vacuous`(테스트가 그대로 통과) → 테스트를 고친다. `invalid`(컴파일 안 됨)·`no_match`·`unsafe`(사본 밖으로 가는 링크) → 변이를 고친다. `timeout`·`other_failure` → 판정 보류, 원인을 본다. 테스트를 지우거나 변이를 바꿔 통과시키지 않는다.
   - 사본에서 돈다. 큰 디렉터리는 `--ignore`로 뺀다. 시간에 민감한 시험이 있으면 `--jobs`를 낮추거나 `--timeout`을 늘린다.
5. **전후 비교와 양성 대조.**
   ```
   python3 -I scripts/diffcheck.py --base "$BASE_CMD" --cand "$CAND_CMD" \
     [--stdin input.json] [--normalize "$VOLATILE_REGEX"] [--stderr] --determinism [--timing 21] --json
   ```
   - 판정: `identical`(종료 0) / `differs`·`empty`·`failed`·`nondeterministic`(종료 1) / 실행 불가·사용법 오류(종료 2 — 통과가 아니다).
   - `--determinism`이 A/A다. 각 쪽을 두 번 돌려 종료 코드·출력이 같은지 본다.
   - 손으로 고른 입력에 더해 무작위 입력을 넣는다(작은 생성기로 수백~수천 쌍).
   - 한 번은 알려진 차이를 넣은 후보로 돌려 `differs`가 나는지 본다(비교가 아무것도 못 잡는 설정을 거른다).
   - 셸 기능이 필요하면 명령을 `bash -c '...'`로 명시한다(기본은 셸 없이 실행).
6. **성능.** 먼저 `--base X --cand X --timing 21`로 잡음 바닥을 잰다. 그다음 `--timing N`(권장 21)으로 번갈아 잰다. 같은 비교를 두세 번 해서 범위를 보고하고, 절대값보다 비율을 쓴다. 측정 경계(프로세스 단위인지 안인지)와 작업량(작은 경우·큰 경우)을 배포 형태에 맞춘다. 2 vCPU 같은 작은 환경에서는 무거운 작업을 병렬로 돌리지 않는다.
7. **대체 구현.** 경계 입력표를 만들어 원본과 대조한다(`docs/patterns/regression.md` §3-7). 차이가 남으면 고치거나 문서에 적는다. 조용히 두지 않는다.
8. **린트·경고.** 절대 건수가 아니라 기준선 대비 새 경고로 본다.
9. **문서 수치.** 바꾼 수치를 `grep`으로 모든 위치에서 찾는다. 허브 페이지 수치는 `site/claims.json`·`site/figures.json`에서만 고치고 `python3 -I scripts/build_site.py --check`를 돌린다.
10. **보고(PR 코멘트).** 아래 형식. 공개 레포에는 판정·수치·해시만 남긴다.

```
⑦ 회귀 고정 — <대상> @ <sha7>
- 기준: <기준 sha / 구현>   비교: <compared 필드 + 투영 한 줄>   고정: <시각·시드·상태>
- PASS_TO_PASS: <명령> → <n>개 통과 (<갈래>)
- 공허함: vacuity_check <guarded n / 그 밖 n> (<변이 목록 경로>)
- 차분: diffcheck <verdict> · base <bytes> / cand <bytes> · 정규화 <패턴 × 횟수> · A/A <통과/실패>
- 시간: <중앙값 변화율, 번갈아 N회, 측정 간 범위, 잡음 바닥>
- 남는 차이·미확인: <없으면 "없음(위 범위 안에서)">
```

## 3. 하지 않을 것

- 빈 출력·실패·시간 초과·비결정성을 "같다"로 보고하지 않는다.
- 비교 범위를 넘는 말("화면이 같다", "동작이 같다")을 쓰지 않는다.
- 회귀 테스트가 실패하면 기준이 아니라 코드를 먼저 의심한다. 테스트를 고쳐 통과시키지 않는다.
- 측정 한 번의 값을 결론으로 쓰지 않는다. 잡음 바닥보다 작은 변화를 효과로 쓰지 않는다.
- 도구 실패(종료 코드 2)를 "결과 없음"으로 읽지 않는다.
