# aok-regress — 회귀 고정 런북

규범: `docs/patterns/regression.md`. 이 스킬은 그 절차를 실행 순서로 줄인 것이다.

## 1. 먼저 정할 것

| 질문 | 답에 따라 |
|---|---|
| 기준이 무엇인가 | 기준 커밋 sha(또는 기준 구현 경로)를 적는다. 기준이 없으면 ⑦이 아니라 ①이다 |
| 무엇을 비교하나(투영) | 출력 전체, 일부 필드, 파일 집합 중 무엇인지 한 줄로 적는다. 보고서의 "같다"는 이 범위까지만이다 |
| 비결정 요소가 있나 | 시각, 난수, 세션·캐시 상태, 경로·시간 표기. 옵션으로 고정하거나 `--normalize`로 지우고 몇 번 지웠는지 보고한다 |

## 2. 실행 순서

1. **기준 고정.** 시각·시드를 옵션으로 고정한다. 상태를 기억하는 도구(세션별 기록, 캐시)에는 실행마다 새 키를 준다. `diffcheck.py`는 명령 인자와 `--stdin` 파일 안의 `{nonce}`를 실행마다 새 토큰으로 바꾼다.
2. **FAIL_TO_PASS.** 버그 수정이면 실패하는 테스트를 먼저 만들고 실패 출력을 보존한다. 고친 뒤 통과를 본다.
3. **PASS_TO_PASS.** 전체 테스트를 돌린다. 선택 의존성이 있으면 있을 때와 없을 때 둘 다.
4. **공허함 검사.**
   ```
   python3 -I scripts/vacuity_check.py --repo <레포> --test "<테스트 명령>" \
     --mutations <[{"file","old","new","label"}] JSON> --json
   ```
   - 변이 하나는 "보호 장치 하나를 끄는 최소 변경"이다(조건 삭제, 경계 바꾸기, 호출 생략).
   - `vacuous`가 나오면 테스트를 고친다. 테스트를 지우거나 변이를 바꿔 통과시키지 않는다.
   - 원본은 건드리지 않는다(사본에서 돈다). 큰 디렉터리는 `--ignore`로 뺀다.
5. **차분 비교.**
   ```
   python3 -I scripts/diffcheck.py --base "<기준 명령>" --cand "<후보 명령>" \
     [--stdin <입력>] [--normalize '<정규식>'] --determinism [--timing 21] --json
   ```
   - 판정: `identical`(종료 0) / `differs`·`empty`·`failed`·`nondeterministic`(종료 1) / 사용법 오류(종료 2 — 통과가 아니다).
   - 손으로 고른 입력에 더해 무작위 입력을 넣는다(작은 생성기로 수백~수천 쌍).
   - 셸 기능이 필요하면 명령을 `bash -c '...'`로 명시한다(기본은 셸 없이 실행).
6. **성능.** `--timing N`(기본 권장 21)은 번갈아 돈다. 같은 비교를 두세 번 해서 범위를 보고한다. 2 vCPU 같은 작은 환경에서는 무거운 작업을 병렬로 돌리지 않는다.
7. **대체 구현.** 경계 입력표를 만들어 원본과 대조한다(`docs/patterns/regression.md` §3-7). 차이가 남으면 고치거나 문서에 적는다. 조용히 두지 않는다.
8. **문서 수치.** 바꾼 수치를 `grep`으로 모든 위치에서 찾는다. 허브 페이지 수치는 `site/claims.json`에서만 고친다.
9. **보고(PR 코멘트).** 아래 형식.

```
⑦ 회귀 고정 — <대상> @ <sha7>
- 기준: <기준 sha / 구현>   비교 범위: <투영 한 줄>   고정: <시각·시드·상태>
- PASS_TO_PASS: <명령> → <n>개 통과 (<선택 의존성 있음/없음>)
- 공허함: vacuity_check <guarded n / vacuous n> (<변이 목록 경로>)
- 차분: diffcheck <verdict> · base <bytes> / cand <bytes> · 정규화 <패턴 × 횟수>
- 시간: <중앙값 전→후, 번갈아 N회, 측정 간 범위>
- 남는 차이·미확인: <없으면 "없음(위 범위 안에서)">
```

## 3. 하지 않을 것

- 빈 출력·실패·비결정성을 "같다"로 보고하지 않는다.
- 비교 범위를 넘는 말("화면이 같다", "동작이 같다")을 쓰지 않는다.
- 회귀 테스트가 실패하면 기준이 아니라 코드를 먼저 의심한다. 테스트를 고쳐 통과시키지 않는다.
- 측정 한 번의 값을 결론으로 쓰지 않는다.
- 도구 실패(종료 코드 2)를 "결과 없음"으로 읽지 않는다.
