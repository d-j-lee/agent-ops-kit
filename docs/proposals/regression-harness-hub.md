## 1. 왜: AOK에 비어 있는 두 칸

**결정적 비교.** ①은 판단이 필요한 주장을 다루고, sha 비교나 테스트 통과 같은 결정적 비교는 "스크립트로 충분"하다며 범위 밖에 두었다(`docs/patterns/brd.md` §1). 그런데 출발점 세션에서 그 스크립트가 여러 번 스스로 속았다. 사례와 재현은 `reports/2026-10-30-hotspots.md` §5에 있다.

| 함정 | 일어난 일 | 등급 |
|---|---|---|
| 빈 출력끼리 비교 | 훅 측정 스크립트가 세션 ID를 재사용해, 두 번째 실행부터 원본과 패치 출력이 둘 다 빈 문자열인데도 "동일"을 찍었다 | [확인] 같은 ID로 다시 돌리면 306바이트 → 0바이트(`reports/2026-10-30-hotspots/logs/2026-11-01-hooks.txt`) |
| 비교 범위보다 넓은 주장 | diff 이식을 줄 목록만 비교하고 "화면이 같다"고 썼다. 낱말 강조까지 같은 것은 9개 경우 중 3개였다 | [기록됨] |
| 비결정성 | 빌드에 기준 시각을 주지 않으면 같은 입력에서도 `categories.json`이 매번 달라져 "바이트 동일"을 비교할 수 없었다 | [확인] `logs/2026-11-01-build.txt` |
| 의미가 다른 대체 구현 | 표준 `json`을 orjson으로 바꾸자 NaN·큰 수·깊은 중첩에서 동작이 달라졌다. 기존 테스트 277개는 그대로 통과했다 | [기록됨] 독립 검증자의 실험 |
| 공허한 테스트 | 수정마다 만든 회귀 테스트 중 4개가, 보호하려던 코드를 지워도 통과했다 | [기록됨] 검증 라운드 2·3 |
| 측정 잡음 | 같은 훅의 절대 중앙값이 날과 호출 방식에 따라 143~278ms로 달랐다. 비율은 몇 %p 안에서 유지됐다 | [기록됨] 10-30·31 값에 원자료가 없다 |

결정적 비교에도 런북과 도구가 있어야 한다는 것이 ⑦의 근거다 [추론]. 이 PR 자신의 검증(§7)도 같은 결론을 냈다. ⑦ 도구의 첫 판이 바로 위 함정의 변형(다른 바이트를 같다고 봄, 문서에 적은 장치를 지키지 못하는 시험)에 빠져 있었다.

**작업 레포 안.** AOK는 허브와 세션의 층을 다룬다. 자식(dev)이 실제로 코드를 고치는 작업 레포 안에는 장치가 없다. 편집 직후 검사, 턴 종료 게이트, 사람·에이전트·CI가 같이 쓰는 단일 검증 진입점, 적대적 리뷰어가 그 칸이다. ④ 루프와 ③ 클린룸이 대상 레포에서 돌 때 이 칸이 비어 있으면, 깨진 코드로 끝난 턴을 사람이 PR에서 처음 본다 [추론]. 출발점 세션의 Rust 하네스(1회차)가 이 칸을 채운 예다. ⑧은 그것을 언어 중립 코어와 언어 어댑터로 나눠 AOK 성격(프로젝트와 무관한 재사용)에 맞춘다.

## 2. 대응표: 교차 · 적대 · 회귀를 AOK의 말로

| 출발점 세션의 말 | AOK | 비고 |
|---|---|---|
| 교차검증 — 다른 눈으로 봐도 같은가 | ① L1 블라인드 + 판정자, v2 사다리 V2·V4 | 결론을 숨긴 독립 판단 |
| 적대적 검증 — 어떻게 하면 깨지는가 | ① L0 검토, L1 "반례 탐색" 렌즈, ④ reviewer | 실험으로 재현한 것만 채택(S8과 같음) |
| 재현 | ① L2, ③ 클린룸, v2 V3 | 원격 자식은 로그만, 판정은 S7 |
| **회귀검증** — 고친 뒤에도 전에 되던 것이 되는가 | **없음 → ⑦** | 기준 고정 + 양성·음성 대조 + 자동 반복 |
| 라운드 R0–R3와 멈춤 기준 | ④ 종료 조건(critical·high·medium 0, 최대 3라운드) | 같은 기준이다. ⑦은 라운드마다 회귀를 고정한다 |
| 근거 4등급(확인·도출·추론·미확인) | §2.1 여섯 등급 | 여섯 등급을 쓴다 |

⑦과 ①은 나눠 맡는다. 비교의 실행과 판정은 ⑦이 기계로 하고, 그 비교가 무엇을 증명하는지(투영, 대표성, 잡음 바닥)는 ①이 판단한다. T2 PR이면 ⑦ 결과를 L0 packet에 넣는다(`docs/patterns/brd.md` §1).

## 4. 읽기 허브

| 항목 | 내용 |
|---|---|
| 목적 | 사람이 AOK를 이해하고 남에게 보여 주는 읽기 화면. 규범은 `docs/`가 정본이고 허브는 그 설명이다. 허브에서 새 규범을 만들지 않는다. 등급 범례는 §2.1을 그대로 옮긴다 |

## 6. 위험

| 위험 | 대응 |
|---|---|
| 기능이 늘어 키트가 무거워진다 | ⑦은 런북 하나와 stdlib 스크립트 둘이다. 원장·스키마 구조는 그대로다 |
| 허브와 `docs/`가 두 벌이 된다 | 허브는 설명만 하고 정본 문서를 가리킨다. 빌드가 허브의 레포 내부 링크가 git에 있는 파일을 가리키는지 보고, 등급 범례는 손으로 쓰지 못하게 하고 규범(`docs/architecture.md`)의 문구로 만든다(시험이 두 문구가 같은지 본다) |
| 공개 레포 위생 | 세션·트리거 ID와 Artifact URL을 쓰지 않는다. `secret_scan.py --strict`. 검증 기록은 집계와 발견의 부류만 남기고 개별 공격 형태는 싣지 않는다 |
