## 1. 왜: AOK에 비어 있는 두 칸

**결정적 비교.** ①은 판단이 필요한 주장을 다루고, sha 비교나 테스트 통과 같은 결정적 비교는 "스크립트로 충분"하다며 범위 밖에 둔다(`docs/patterns/brd.md` §1). 그런데 출발점 세션에서 그 스크립트가 여러 번 스스로 속았다.

| 함정 | 일어난 일 | 등급 |
|---|---|---|
| 빈 출력끼리 비교 | 훅 측정 스크립트가 세션 ID를 재사용해, 두 번째 실행부터 원본과 패치 출력이 둘 다 빈 문자열인데도 "동일"을 찍었다 | [확인] 같은 ID로 두 번 실행하면 306바이트 → 0바이트 |
| 비교 범위보다 넓은 주장 | diff 이식을 줄 목록만 비교하고 "화면이 같다"고 썼다. 낱말 강조까지 같은 것은 9개 경우 중 3개였다 | [확인] |
| 비결정성 | 빌드에 기준 시각을 주지 않으면 같은 입력에서도 `categories.json`이 매번 달라져 "바이트 동일"을 비교할 수 없었다 | [확인] |
| 의미가 다른 대체 구현 | 표준 `json`을 orjson으로 바꾸자 NaN·큰 수·깊은 중첩에서 동작이 달라졌다. 기존 테스트 277개는 그대로 통과했다 | [기록됨] 독립 검증자의 실험. 고친 뒤 [확인] |
| 공허한 테스트 | 수정마다 만든 회귀 테스트 중 4개가, 보호하려던 코드를 지워도 통과했다 | [기록됨] 검증 라운드 2·3 |
| 측정 잡음 | 같은 훅 비교를 여러 번 재면 편집 훅 단축 비율이 -32%~-50% 사이에서 흔들렸다 | [확인] 출발점 세션의 측정 3회 |

결정적 비교에도 런북과 도구가 있어야 한다는 것이 ⑦의 근거다 [추론].

**작업 레포 안.** AOK는 허브와 세션의 층을 다룬다. 자식(dev)이 실제로 코드를 고치는 작업 레포 안에는 장치가 없다. 편집 직후 검사, 턴 종료 게이트, 사람·에이전트·CI가 같이 쓰는 단일 검증 진입점, 적대적 리뷰어가 그 칸이다. ④ 루프와 ③ 클린룸이 대상 레포에서 돌 때 이 칸이 비어 있으면, 깨진 코드로 끝난 턴을 사람이 PR에서 처음 본다 [추론]. 출발점 세션의 Rust 하네스가 이 칸을 채운 예다. ⑧은 그것을 언어 중립 코어와 언어 어댑터로 나눠 AOK 성격(프로젝트와 무관한 재사용)에 맞춘다.

## 2. 대응표: 교차 · 적대 · 회귀를 AOK의 말로

| 출발점 세션의 말 | AOK | 비고 |
|---|---|---|
| 교차검증 — 다른 눈으로 봐도 같은가 | ① L1 블라인드 + 판정자, v2 사다리 V2·V4 | 결론을 숨긴 독립 판단 |
| 적대적 검증 — 어떻게 하면 깨지는가 | ① L0 검토, L1 "반례 탐색" 렌즈, ④ reviewer | 실험으로 재현한 것만 채택(S8과 같음) |
| 재현 | ① L2, ③ 클린룸, v2 V3 | 원격 자식은 로그만, 판정은 S7 |
| **회귀검증** — 고친 뒤에도 전에 되던 것이 되는가 | **없음 → ⑦** | 기준 고정 + 자동 반복 + 공허함 방지 |
| 라운드 R0–R3와 멈춤 기준 | ④ 종료 조건(critical·high·medium 0, 최대 3라운드) | 같은 기준이다. ⑦은 라운드마다 회귀를 고정한다 |
| 근거 4등급(확인·도출·추론·미확인) | §2.1 여섯 등급 | 여섯 등급을 쓴다 |

## 4. 읽기 허브

| 항목 | 내용 |
|---|---|
| 목적 | 사람이 AOK를 이해하고 남에게 보여 주는 읽기 화면. 규범은 `docs/`가 정본이고 허브는 그 설명이다. 허브에서 새 규범을 만들지 않는다 |
| 경로 | 원본 `site/pages/*.html` · 공용 `site/assets/` · 수치 `site/claims.json`(claim 스키마) → `python3 scripts/build_site.py` → `site/dist/`(git 밖) → Artifact로 게시 |
| URL | 관제실처럼 레포에 쓰지 않는다. 사용자에게 받아 허브 메모에 둔다 |
| 수치 레지스트리 | 결론을 받치는 수치(전후 비교, 검증 건수, 연구 수치)는 본문에 직접 쓰지 않고 `{{fig:<id>}}`로 쓴다. 값과 등급, 범위, 근거는 레지스트리에서 채우고 페이지마다 근거 표를 만든다. 같은 수치가 여러 페이지에서 어긋나는 문서 회귀를 구조로 막는다. 빌드는 모르는 id, 근거 없는 [확인], 쓰이지 않는 항목, 없는 파일 링크, Artifact URL·세션 ID를 실패로 처리한다. 줄 수·파일 수 같은 맥락 수치는 본문에 둔다 |
| 범위 | 허브 페이지만. `reports/`는 그 날짜의 값으로 남기는 이력이라 레지스트리 밖이다 |
