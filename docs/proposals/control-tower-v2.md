## 0. 목표

사람과 여러 AI 세션의 협업을 체계적으로 관리한다. 진행 중인 모든 세션을 한 곳에서 본다. 공이 사람에게 넘어온 일만 골라 우선순위대로 내밀어, AI가 사람을 기다리는 시간과 사람이 놓치는 일을 줄인다. 세션의 주장은 그 세션과 독립된 눈으로 확인한다. 개입은 사람이 승인한 만큼만 한다. 결정은 기록해 두었다가 다음에 다시 쓴다.

## 2. 원칙

1. **메타데이터 먼저.** 인박스는 `status_bucket`·`needs_action`·`status_detail`·맥락으로 만든다. 대화 기록은 카드를 만들거나 검증할 때만, 그것도 증분으로 읽는다. 빠르고 예측 가능하며 주입 위험이 적기 때문이다.
2. **사람 세션의 결정은 사람이 그 세션에서 한다.** 기본 개입은 "답 복사 + 세션 열기"다. 받는 세션은 다른 세션이 보낸 메시지를 동료 데이터로 취급한다 [문서]. 그래서 메시지로는 결정을 대신 전할 수 없다.
3. **초인종과 주문서.** 콘솔이 매니저에게 일을 시킬 때는 원장에 주문서(`requests`)와 사용자 승인을 쓰고, `send_message`로는 깨우기만 한다. 매니저는 메시지가 아니라 원장의 승인 기록을 근거로 움직인다(S5).
4. **독립성.** 검토자는 대상 세션의 맥락을 공유하지 않는다. 메모리 없는 `sample`, 새 서브에이전트, 원격 세션 중 하나를 쓴다. 수치는 숨기고 원천(이벤트, 레포)을 보게 한 뒤 기계로 대조한다. 작성 세션에 "맞냐"고 다시 묻지 않는다. 그것은 자기 신고일 뿐이다.
5. **가벼운 것부터.** 결정적 규칙 → 클릭할 때만 LLM → 판정은 effort가 있는 매니저(S7) → 재실행은 원격 자식 순서로 쓴다. 기준은 응답 속도, 예측 가능성, 독립성이다.
6. **자율은 단계적이고 명시적이다.** 기본은 A1(초안)이다. A3(자동)는 범위와 만료일을 붙여 사전 위임한 규칙에만 쓰고, 감사 기록을 남긴다.
7. **알림 피로를 막고 스스로 교정한다.** 배지는 주 레인에만 단다. 나머지는 묶음과 브리프로 보낸다. 개입 결과와 기각 사유를 재고, 임계값 조정은 제안만 한다. 자동으로 바꾸지 않는다.

## 2a. 협업 지표

관제탑이 잘하고 있는지는 이것으로 잰다. 콘솔 상단 타일과 브리프에 같은 지표를 쓴다.

| 지표 | 정의 | 원천 | 방향 |
|---|---|---|---|
| 공 보유 | 세션마다 공이 AI에게 있나(WORKING), 사람에게 있나(BLOCKED·`needs_action`·후속) | `list_sessions` | 사람 쪽 비율이 줄어야 한다 |
| 사람 응답 지연 | 사람 차례가 열린 뒤 처리까지 걸린 시간의 중앙값과 최장 | `updated_at`, `inbox_state` | 줄어야 한다 |
| 놓친 후속 | 완료 세션에 남은 사람 몫 중 7일 넘게 열린 것 | H06 + `inbox_state` | 0에 가까워야 한다 |
| 검증된 주장 비율 | 완료형 주장 중 V1 이상으로 확인된 것 | `verifications` | 늘어야 한다 |
| 개입 효과 | 개입 뒤 30분 안에 막힘이 풀린 비율 | `interventions.outcome` | 늘어야 한다 |
| 결정 재사용 | 같은 질문에 이전 결정을 보여 준 횟수(H18) | `decisions` | 늘어야 한다 |
| 인박스 정밀도 | 사용자가 "과민"으로 기각한 비율 | `inbox_state.dismiss_reason` | 20% 이하 |

| 협업 관리 | 공이 누구에게 있는지 보이고, 사람 응답 지연과 인계 품질을 잰다 | 협업 지표(§2a) | 콘솔 규칙 |
| 보고 | 아침 브리프(결정·검증·진척 변화) | `brief` | `sample` / 매니저 |
| 기억 | 결정·목표·미룬 이유를 남기고, 비슷한 질문이 다시 오면 이전 결정을 보여 준다 | `decisions`, H18 | 원장 |
| 위임 | 검증·후속 작업을 매니저에게 넘긴다(입장 검사) | 주문서 | 매니저 |
| 비서: 할 일 | 사람이 해야 할 병합·설치·승인을 놓치지 않는다 | 후속 묶음, 내 할 일 | 콘솔 |
| 비서: 대필 | 막힌 세션에 줄 답을 준비한다 | 선택지 칩, 답 초안 | 콘솔 + `sample` |
| 비서: 질의응답 | "어제 그 PR 어떻게 됐어?"에 답한다 | 비서 채팅 | `sample` + 페이지 도구 |

## 4. 지능 배치

| 층 | 위치 | 하는 일 | 트리거 | 비용 | 한계 |
|---|---|---|---|---|---|
| **D 결정적** | 콘솔 JS | 신호, 인박스, 점수, 중복 제거, 선택지 추출, 주장 정규식, V0 | 갱신 주기 | $0 | 의미를 모른다("진행할까요?"가 무엇을 묻는지) |
| **S 샘플** | 콘솔 `sample`(보는 사람의 계정, 메모리 없음) | 카드 소화, 답 초안, 브리프 문장, 비서 채팅 | **사용자 클릭 때만**(플랫폼 규칙) [문서] | 사용자 사용량 | 입력 256KiB, 타이머 금지, rate_limited 가능 [문서] |
| **M 매니저 세션** | UI에서 만든 전용 세션(effort 있음 [확인]) + AOK 스킬 | 심층 소화, 주장 원장, 검증 판정, 예약 브리프, 큐레이션 | 콘솔 주문서 + 초인종, 자기 `send_later`, 예약(T1 통과 후) | 오래 살수록 커진다 | 교대 필수. 이벤트 읽기는 서브에이전트에 맡긴다 |
| **R 원격 검증** | `create_session` 자식(repro-l2, cleanroom) | V3 재실행, 클린룸 | 매니저의 입장 검사 뒤 | 첫 턴 약 $0.27 + 실행 [확인: field-test] | 판정 금지(S7). 분 단위. 레포 없는 주장에는 쓸 수 없다 |

콘솔에는 앞으로도 `create_session`을 넣지 않는다. 검증을 누르면 콘솔은 주문서와 사용자 승인을 원장에 쓰고, 매니저에게 초인종만 보낸다.

## 5. 데이터 모델 (전부 비공개 원장 = 콘솔 Artifact DB)

| 키 | 핵심 필드 | 쓰는 쪽 |
|---|---|---|
| `inbox_state/<item_key>` *(구현됨)* | `status`(open/snoozed/done/dismissed), `snooze_until`, `sig`, `kind`, `session_id`, `updated_at`. 추가 예정: `dismiss_reason`(과민/이미 처리/무관) | 콘솔 |
| `ctx/<session_id>` 작업 맥락 카드 | 관측: `origin, repo, ws_id, sig`. 소화: `goal, state, next_user_action, options[{label, ref}], followups[{text, owner, ref}], claims[{cid, kind, value, ref_hint{pr, sha, branch}, src_ref, grade:"기록됨", vstate}], digest{at, by, cursor, input_bytes}`. 사용자: `note, pin` | 콘솔(S), 매니저 |
| `ws/<ws_id>` 워크스트림 | `name, repos[], session_ids[], goal, confirmed` | 규칙이 제안하고 사용자가 확정 |
| `requests/<req_id>` 주문서 | `kind`(verify_claims/cleanroom/deep_brief/delegate), `target_session, params, approved{by, at}, status`(queued/taken/done/failed), `taken_by, result_ref, budget_usd` | 콘솔이 만들고 매니저가 처리 |
| `interventions/<iv_id>` | `session_id, item_key, channel, autonomy, draft{text, by, src_refs}, approved{by, at}, exec{at, result}, check_at, outcome`(unblocked/no_change/regressed) | 콘솔 |
| `decisions/<dec_id>` | `session_id, ws_id, question, chosen, alternatives, rationale, at, via, supersedes` | 사용자(콘솔). 매니저는 기록만 |
| `brief/<YYYY-MM-DD>` | `by, counts, top[], waits{median_h, max_h}, followups_open, verify, text`. 비용은 `ref_cost`로 참고만 | `sample` / 매니저 |
| `config/autonomy` | `rules[{channel, scope{origin, tags, ws}, level, granted_at, expires_at}]` | 사용자만 |
| `verifications/<run_id>` *(v1 확장)* | `+target{session_id, cid}, rung, verdict`(일치/반박/검증불가), `ref` | 매니저 |

- 소화 필드는 모두 `ref`(`session_<id>/<event_uuid>` 또는 `sd@<updated_at>`)를 갖는다. 검증 전까지 등급은 `기록됨`이다.
- 발췌는 200자 이하, 카드는 16KB 이하로 둔다. 원장 한도(문서 256KB·25,000개 [문서]) 안에서 세션 1,000개를 담을 수 있다 [도출].
- 인박스 항목은 매번 계산하고 사람의 처리 상태만 저장한다. 서명이 바뀌면 다시 연다.
- 공개 레포에는 `schemas/ledger.schema.json`의 정의, 규칙 코드, 합성 픽스처만 둔다.

**갱신 계층 (서명·커서 기반 증분)**

| 층 | 언제 | 읽기 | 쓰기 | 비용 |
|---|---|---|---|---|
| R0 관측 | `watchTool` 주기 | `list_sessions` 60건 | 서명(`bucket, updated_at, needs_action, status_detail`)이 바뀐 것만 다시 계산 | $0 |
| R1 증분 | 카드를 열거나 "갱신"을 누를 때 | `list_events(kinds=[result], after_id=cursor, limit≤20)` | 정규식으로 주장·후속을 뽑고 커서를 전진 | $0. 페이지 크기는 F4로 잰다 [미확인] |
| R2 소화 | "정리"를 누를 때(한 번에 10건 이하) | 카드 + 최근 result 48KB 이하 | `goal, state, options, followups` | 사용자 사용량, `sample` quick |
| R3 심층 | 매니저: 검증·브리프·주간 정리 | `scripts/harvest_events.py`로 정제한 이벤트 | event_uuid가 붙은 주장 원장 | 서브에이전트 165k–320k 토큰 [확인: brd.md] |

서명과 커서가 그대로면 다시 소화하지 않는다.

| H09 | 맥락 600k 이상이고 미완료. 400k 이상은 표시만 | context / 주 | ✓(600k) |
| H10 | WORKING, 1시간 동안 활동(토큰·비용 증가)은 있는데 새 result가 없음(진전 없는 반복) | loop_suspect / 주 | 계획(P3, 시계열 필요) |
| H11 | 같은 레포에 활성 세션 2개 이상 | coordination / 주 | ✓ |
| H12 | 정규화한 제목이 같거나, 짧은 쪽 토큰이 긴 쪽에 포함(7일 안) | 워크스트림 묶기 제안 | 계획(P1) |
| H13 | 비용 0, 맥락 0, 24시간 이상 | cleanup / 묶음 | 계획(P1) |
| H14 | 맥락 0인데 비용 > 0 | "요약 받아 새 세션" 제안 | 계획. 의미 미확인(F3) |
| H15 | REVIEW_READY 72시간 이상 → review, 14일 이상 → cleanup | review / 주 | ✓(72시간) |
| H16 | `needs_action`에 `/config`·settings·permission rule·auto mode·설정 변경 | "설정·권한 변경 요청" 문구. 조치 없음(S4·S8) | ✓ |
| H17 | `role:manager` 세션 | H09·H10만 적용 | 계획(P3) |
| H18 | 새 `needs_action`이 같은 워크스트림의 `decisions.question`과 비슷함 | 이전 결정 표시 | 계획(P1) |
| H19 | 세션 레코드의 `unread: true`(끝났는데 사용자가 아직 보지 않은 결과) | unread / 묶음, 브리프 첫 줄 | 씨앗. 필드 존재만 확인 [확인, n=1]. 의미 시험 필요 |
| H20 | `external_metadata.rate_limit_info`의 `status`가 allowed가 아님, 또는 리셋 시각 임박 | 상태 띠 표시("한도 리셋 hh:mm") | 씨앗. 필드 존재 [확인], allowed 밖의 값은 [미확인] |
| H21 | `external_metadata.artifacts`(세션이 만든 아티팩트 목록) | 작업 카드의 "산출물" 링크 | 씨앗 [확인: 필드 존재] |

**점수:** 결정류(approval·merge·decision)는 `base + 대기 min(15, 3·log2(h+1))`, review는 `base + 대기 가산/3`, 나머지는 base만이다. 비용은 점수에 넣지 않는다. base는 approval 95, merge 90, decision 85, failed 80, stall 70, followup 60, review 50, context 45, coordination 35, cleanup 10이다. 반박된 검증 결과는 90으로 둔다(P3).

## 7. 개입 카탈로그와 자율 수준

자율 수준: **A0** 표시만 · **A1** 초안(사람이 고치고 두 번 눌러 실행) · **A2** 원클릭(내용 고정, 두 번 눌러 실행) · **A3** 자동 + 사후 통지(사전 위임·만료일 필수, 감사 기록).
실행 권한: 콘솔 조작은 보는 사람의 권한으로, 매니저 조작은 매니저 세션의 권한으로 실행된다 [문서].

| 채널 | 수단 | 위험 | 기본 | 사전 위임(A3) 가능 범위 |
|---|---|---|---|---|
| 세션 열기 | `https://claude.ai/code/<session_id>` [문서] | 없음 | 항상 | — |
| 답 복사 + 열기 | 선택지 칩 또는 초안 → 클립보드 → 세션 열기 | 낮음(보내는 건 사람) | A2 | — |
| 메시지 전송 | `send_message(later)` | 중간: 깨우면 턴 비용이 든다. 받는 쪽은 동료 데이터로 다룬다 [확인] | 자식 A1. 사람 세션은 D11 전까지 금지 | 트리 자식 상태 확인 |
| 동료 조율 | 두 세션에 `send_message` | 중간 | A1 | 없음 |
| 중단 | `interrupt_session` | 높음: 진행 중 작업 손실 | A1 | 트리 자식이 `cap_over`이고 `on_overrun=interrupt`일 때만 |
| 보관 | `archive_session`(되살릴 수 있음) | 중간, S4 | A1 일괄 | 빈 자식 세션(H13), 7일 이상(D14) |
| 검증 요청 | 주문서 + 사용자 승인 + 초인종 | 매니저 시간 | A2, 예상 소요 표시 | V0는 자동 |
| 태그·워크스트림 | `set_session_tags` | 낮음 | A2 | `ws:<id>` 태그 |
| 권한 승인, 병합, 설정 변경 | — | — | 콘솔에서 하지 않는다 | 불가 |

모든 개입은 `interventions`에 남기고 30분 뒤 결과(`outcome`)를 잰다. 이것이 휴리스틱을 교정하는 근거가 된다.

## 9. 콘솔 UX

```
[결정 3 · 승인 1 · 병합 2 · 조율 2 · 맥락 1 | 응답 대기 최장 13일 · 중앙값 2일 | 갱신 hh:mm | ▶ 브리프]
┌ 당신 차례 (주 레인, 점수순) ─────────┐┌ 워크스트림 ─────────┐
│ 결정 · <제목> 13일 · 사람             ││ <레포 A> 4 ⚠ 동시   │
│   [칩1] [칩2] [답 복사+열기] [미루기] ││ <레포 B> 2           │
│ 승인 · <제목> 50시간 · 사람  [열기]   │├ 검증 큐 ────────────┤
├ 묶음: 후속 8 · 정리 8 ───────────────┤│ V1 PR 상태 대기      │
└──────────────────────────────────────┘└─────────────────────┘
[비서 ▸ ]
```

폰에서는 상태 띠 → 주 레인 → 탭 순서로 쌓는다.

| kind | 1차 행동 | 2차 행동 |
|---|---|---|
| decision | 선택지 칩 → 답 복사 + 열기 | 결정 기록, 미루기(4시간/1일/1주), 정리(`sample`) |
| approval | 열기 | 미루기 |
| merge | 세션 열기 + V1 요청 | 처리함 |
| review | 열기 | 검증 요청, 정리 |
| followup | 내 할 일로 / 처리함 | 매니저에게 새 세션 제안 |
| coordination | 워크스트림 묶기 | 조율 메시지 초안 |
| context | 인계 요청문 복사 | 무시 |
| cleanup | 일괄 보관(선택 + 두 번 클릭) | 유지 |
| 검증 결과 | 근거 열기 | 반박 내용을 답 초안으로 |

**선택지 칩(결정적):** `needs_action`의 "choose:/pick:/중 선택:" 뒤를 `/`·`,`·` or `로 나눈다. 칩을 누르면 그 문구를 복사하고 세션을 연다. 아티팩트 안에서 클립보드 쓰기가 막히면 선택 가능한 입력란으로 대신 보여 준다 [미확인].

**비서 채팅(`sample` + 페이지 도구):**
- 읽기 도구: `inbox.list`, `card.get`, `ws.get`, `ledger.search`, `events.peek(session_id, ≤20, result만)`.
- 제안 도구: `propose(channel, target, draft)`. 제안은 실행 버튼이 달린 카드로만 그려진다. 모델이 직접 실행하지는 못한다.
- `sample`은 메모리가 없다 [문서]. 그래서 호출할 때마다 원장에서 카드와 결정을 다시 싣는다.

**아침 브리프:** 클릭하면 R0를 다시 계산하고 `sample`을 한 번 부른다(30KB 이하). T1·T3을 통과한 뒤에는 매니저의 예약 작업이 `brief/<day>`를 쓰고 알린다. 내용은 결정 상위 5개(각각 추천 한 줄), 어제 완료와 검증 상태, 숨은 후속, 진척이 멈춘 세션, 정리 후보, 위험이다. 비용은 맨 끝에 참고로 한 줄만 둔다.
