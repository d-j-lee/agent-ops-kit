## 0. 목표

사람과 여러 AI 세션의 협업을 체계적으로 관리한다.

- 진행 중인 모든 세션을 한 곳에서 본다.
- 공이 사람에게 넘어온 일만 골라 우선순위대로 내민다. AI가 사람을 기다리는 시간과 사람이 놓치는 일을 줄이기 위해서다.
- 세션의 주장은 그 세션과 독립된 눈으로 확인한다.
- 개입은 사람이 승인한 만큼만 한다.
- 결정은 기록해 두었다가 다음에 다시 쓴다.
- 사람에게 묻는 일 자체도 줄인다. 관제탑이 질문을 늘리면 그것이 새 병목이 된다.

## 2. 원칙

1. **메타데이터 먼저.** 인박스는 `status_bucket`·`session_status`·`needs_action`·`status_detail`·`recent_action`·`unread`·맥락으로 만든다. 대화 기록은 카드를 만들거나 검증할 때만, 그것도 증분으로 읽는다. 빠르고 예측 가능하며 주입 위험이 적기 때문이다.
2. **사람 세션의 결정은 사람이 그 세션에서 한다.** 기본 개입은 "선택지 복사 + 세션 열기"다. 받는 세션은 다른 세션이 보낸 메시지를 동료 데이터로 취급한다 [문서: send_message 설명. 확인: v1 자식 D가 `/effort`를 평문으로 받고 따르지 않음]. 그래서 메시지로는 결정을 대신 전할 수 없다.
3. **원장은 인증 경계가 아니다.** 원장 쓰기는 콘솔이든 자식이든 모두 사용자 이름으로 기록된다 [문서: ArtifactData 설명]. URL을 아는 세션이나 주입당한 세션은 승인 기록을 꾸밀 수 있다 [도출]. 그래서 다음 원칙을 둔다.
   - 콘솔이 매니저에게 일을 시킬 때는 원장에 주문서(`requests`)를 쓰고 `send_message`로 깨우기만 한다(초인종과 주문서).
   - 읽기 전용이고 범위가 좁은 주문(V0–V2)만 원장 기록으로 실행한다.
   - 위험한 주문은 매니저가 **자기 UI 세션에서 사람에게 다시 확인**받은 뒤 실행한다. 세션 생성, 중단, 보관, 사람 세션으로의 전송이 여기에 든다(S4·S5).
4. **독립성.** 검토자는 대상 세션의 맥락을 공유하지 않는다(메모리 없는 `sample`, 새 서브에이전트, 원격 세션). 수치는 숨기고 원천(이벤트, 레포)을 보게 한 뒤 기계로 대조한다. 작성 세션에 "맞냐"고 다시 묻지 않는다. 자기 신고일 뿐이기 때문이다.
5. **가벼운 것부터.** 규칙층 → 클릭할 때만 샘플층 → 판정은 effort가 있는 매니저층(S7) → 재실행은 원격층 순서로 쓴다. 기준은 응답 속도, 예측 가능성, 독립성이다.
6. **자율은 단계적이고 명시적이다.**
   - 기본은 A1(초안)이다.
   - A3(자동)는 범위와 만료일을 붙여 사전 위임한 규칙에만 쓴다.
   - S4에 든 조작(보관, 중단 등)은 사람이 `CLAUDE.md`를 바꾸기 전에는 A3가 될 수 없다.
7. **알림 피로를 막고 스스로 교정한다.**
   - 배지는 결정류에만 단다. 나머지는 묶음과 브리프로 보낸다.
   - 개입 결과와 무시 사유를 잰다.
   - 임계값 조정은 제안만 하고 자동으로 바꾸지 않는다.
8. **사람에게 묻는 양을 줄인다.** 결정은 권장 기본값으로 시작하고 사람은 반대할 것만 말한다(옵트아웃). 질문은 사람만 답할 수 있는 것으로 한정한다.

## 2a. 협업 지표

관제탑이 잘하고 있는지는 아래 지표로 잰다. 콘솔 타일과 브리프에 같은 지표를 쓴다.

| 지표 | 정의 | 원천 | 방향 | 상태 |
|---|---|---|---|---|
| 공 보유 | 세션마다 공이 AI에게 있나(WORKING), 사람에게 있나(결정류·후속·안 읽은 결과) | `list_sessions` | 사람 쪽 비율이 줄어야 한다 | 타일 ✓ |

## 4a. Rust 적용 (2026-10-30)

**원칙.** Rust는 측정과 검사를 결정적으로 하는 부품에 쓴다. AI 덕분에 코드를 쓰는 비용은 줄었지만, 읽고 소유하는 비용은 그대로다. 병목은 검증으로 옮겨 갔다. 그래서 Rust로 옮기는 이유는 측정·검사의 질이어야 한다. 언어를 바꾸는 것 자체는 이유가 되지 않는다. 컴파일러와 린트·시험 게이트가 AI가 쓴 코드의 첫 검토자 역할을 하는 곳이 Rust의 자리다.

|---|---|---|---|---|
| **R1** | 사용자의 Rust CLI **fsmap**(공개 레포 `d-j-lee/filesystemMap`)을 작업공간 측정 엔진으로 쓴다. 세션이 자기 컨테이너를 재서 원장 `atlas/<session_id>`에 올린다(`aok-atlas`, `scripts/atlas_record.py`) | 미저장 산출물(IN24) 판정이 요약 문구 추정에서 git 실측으로 바뀐다(미커밋·추적 안 된 파일·stash·앞선 커밋·업스트림 없는 브랜치). 작업공간 규모와 재생성 가능한 빌드 산출물(세션 디스크는 고정 할당)도 보인다 | 구현. 콘솔 v12. | **R3** | 인박스 규칙 코어를 Rust 한 벌로 만들어 네이티브 CLI와 WASM(콘솔)에 같이 쓴다 | 지금 규칙은 콘솔 JS에만 있어 매니저 세션이 같은 판정을 낼 수 없다. 한 벌이면 시험도 한 곳에 모인다 | 씨앗. R1의 효용을 1–2주 본 뒤 | D24 |

- **R1 실측** [확인: 이 세션, 2026-10-30]
  - `/home/user` 스캔(클론 3개): 0.19초, 파일 1,113개
  - 원장 레코드: 1,719바이트
  - 고정 커밋 설치(`cargo install --locked --git … --rev …`): 이 컨테이너에서 1분 7초. CI 러너 시간은 첫 실행 때 잰다
  - 측정한 미커밋 5·추적 안 된 파일 3은 같은 시각 `git status`와 일치했다
- **R1 신뢰 경계.** 측정은 세션이 자기 컨테이너에 대해 올리는 자기 보고다. 원장 쓰기는 모두 사용자 이름이므로 위조를 막지 못한다(§11 원장 위조). 콘솔은 측정 시각을 함께 보이고, 측정이 세션의 마지막 변화보다 30분 넘게 앞서면 "이후 변화"로 표시한다. 저장소 밖 파일은 측정 범위 밖이다.
- **R3 대안.** 더 작은 시작점으로 `secret_scan.py`를 Rust로 옮기는 L1 시범이 있다. 같은 입력에 두 구현을 돌려 결과를 비교하는 차등 시험이 필요하다. 효용은 R3보다 작다(지금 스크립트가 느리거나 틀린 증거가 없다).
- **권하지 않는 것:**
  - 콘솔을 Rust UI 프레임워크로 다시 쓰는 것. Artifact 제약(고정 버전 CDN, 크기)이 있고, 소유 비용이 커진다.
  - 표준 라이브러리 Python 스크립트를 통째로 옮기는 것. 작고 시험이 있으며, 느리다는 증거가 없다.

- 공개 레포에는 `schemas/ledger.schema.json`의 정의, 규칙 코드, 합성 픽스처만 둔다.

**갱신 단계 (서명·커서 기반 증분)**

| 단계 | 언제 | 읽기 | 쓰기 | 부담 |

**보는 범위의 한계.**
- `list_sessions` 기본 목록은 Cowork 세션과 예약 작업이 띄운 세션을 뺀다 [문서].
- 태그로 포함시키는 옵션은 OAuth 호출자에게만 열려 있다 [문서]. 콘솔에서 쓸 수 있는지는 F15로 잰다.
- 최근 100개 밖의 오래된 세션은 페이지 넘김을 넣기 전까지 보이지 않는다.

**점수:**
- 결정류(approval·merge·decision): `base + 대기 min(15, 3·log2(h+1)) − 감쇠 − 대체 30`.
- review_stale: `base + 대기 가산/3`. 나머지는 base만 쓴다.
- 비용은 점수에 넣지 않는다.
- base: approval 95, merge 90, decision 85, failed 80, volatile 75, stall 70, followup 60(14일 뒤 40), unread 55, review_stale 50, context 45, same_repo 35, hygiene 10. 반박된 검증 결과는 90(P1).

## 7. 개입 카탈로그와 자율 수준

자율 수준:
- **A0** 표시만.
- **A1** 초안. 사람이 고치고 두 번 눌러 실행한다.
- **A2** 원클릭. 내용은 고정이고, 두 번 눌러 실행한다.
- **A3** 자동 + 사후 통지. 사전 위임과 만료일이 필수이고 감사 기록을 남긴다. S4 조작은 할 수 없다.

실행 권한: 콘솔 조작은 보는 사람의 권한으로, 매니저 조작은 매니저 세션의 권한으로 실행된다 [문서].

| 채널 | 수단 | 위험 | 기본 | 사전 위임(A3) |
|---|---|---|---|---|
| 세션 열기 | `https://claude.ai/code/<session_id>` [문서] | 없음 | 항상 | — |
| 선택지 복사 + 열기 | `needs_action`에서 뽑은 선택지 라벨만 복사 → 세션 열기 | 낮음(보내는 건 사람, 문구는 세션 자신의 것) | A2 | — |
| 자유문 답 초안 | 샘플층이 쓴 초안 → 복사 | 중간: 다른 세션 기록에서 나온 문장이 사람 권한의 지시로 바뀐다(세탁) | A1. 출처를 강조하고, 명령·URL·권한어가 있으면 경고 | 불가 |
| 메시지 전송 | `send_message(later)` | 중간: 받는 쪽은 동료 데이터로 다룬다 | 자식 A1. 사람 세션은 D11 전까지 금지 | 트리 자식 상태 확인 |
| 동료 조율 | 두 세션에 `send_message` | 중간 | A1 | 불가 |
| 중단 | `interrupt_session` | 높음: 진행 중 작업 손실 | A1, 두 번 클릭 | 불가(S4) |
| 보관 | `archive_session` | **높음**: 컨테이너가 반납된다. 되살리면 새 컨테이너가 붙는다 [문서]. 푸시·업로드하지 않은 파일이 사라질 수 있다 | A1. `unread` 세션은 후보에서 뺀다 | 불가(S4) |
| 검증 요청 | 주문서 + 초인종 | 매니저 시간 | V0–V2는 A2, V3 이상은 매니저 UI에서 사람 확인 | V0는 자동 |
| 태그·워크스트림 | `set_session_tags` | 낮음 | A2 | `ws:<id>` 태그 |
| 권한 승인, 병합, 설정 변경 | — | — | 콘솔에서 하지 않는다 | 불가 |

- 샘플층의 `propose` 제안은 target을 소화한 그 세션으로 고정한다. 다른 세션을 겨냥한 제안은 버린다.
- 모든 개입은 `interventions`에 남기고 30분 뒤 결과(`outcome`)를 잰다. 이것이 휴리스틱을 교정하는 근거가 된다.

- 병합·공개 직전의 주장, 또는 다른 세션이나 사람이 그 결과에 기대고 있는 주장은 V1 다음 바로 V3로 간다 [추론].
- 그 단이 허락하는 것보다 등급을 높이지 않는다. 검증불가는 통과로 세지 않는다.
- `sample`의 빠른 의견은 사다리에 넣지 않는다. 문제를 표시할 수는 있지만 등급을 올리지는 못한다.

| 위협 | 대책 |
|---|---|
| 앵커링 | 결론·수치는 숨기고 질문만 준다. 비교는 기계가 한다. 판정자는 별도 서브에이전트다 |
| 대화 기록 주입 | 데이터 경계로 감싸고 `textContent`로만 표시한다. `sample`에는 읽기 도구만 주고 출력은 JSON 스키마(enum, 길이 제한)로 받는다. 출력 속 URL·명령은 비활성 텍스트로 둔다 |
| 사람을 통한 세탁 | 복사 기본값은 세션 자신의 선택지 라벨이다. 자유문 초안에는 출처와 경고를 붙인다(§7) |
| 원장 위조 | 원장 기록은 위험한 조작의 근거가 되지 못한다(원칙 3) |
| 재실행 주입 | 명령은 해당 sha의 레포 파일(CI 워크플로, 패키지 스크립트)에서만 가져온다. 그 밖의 행동은 이탈로 기록한다(클린룸 방식) |
| 설정 유도 | IN16은 문구만 붙인다. 매니저는 메시지를 초인종으로만 다룬다 |

## 9. 콘솔 UX

```
[결정 3 · 승인 1 · 병합 1 | 응답 대기 최장 13일 · 중앙값 2일 | 갱신 hh:mm | ▶ 브리프]
┌ 당신 차례 (점수순) ──────────────────┐┌ 워크스트림 ─────────┐
│ 결정 · <제목> 13일 · 사람             ││ <레포 A> 4 ⚠ 동시   │
│   [칩1] [칩2] [열기] [미루기] [무시…] ││ <레포 B> 2           │
│ 승인 · <제목> 50시간 · 사람  [열기]   │├ 검증 큐 ────────────┤
├ 묶음: 후속 9 · 안 읽음 2 · 정리 3 ───┤│ V1 PR 상태 대기      │
└──────────────────────────────────────┘└─────────────────────┘
[비서 ▸ ]
```

폰에서는 상태 띠 → 결정류 → 탭 순서로 쌓는다.

| kind | 1차 행동 | 2차 행동 |
|---|---|---|
| decision | 선택지 칩 → 복사 + 열기 | 결정 기록, 미루기, 무시(사유), 정리(`sample`) |
| approval | 열기 | 미루기 |
| merge | 세션 열기 + V1 요청 | 처리함 |
| followup | 내 할 일로 / 처리함 | 매니저에게 새 세션 제안 |
| unread | 열기 | 처리함 |
| review_stale | 열기 | 검증 요청, 정리 |
| same_repo | 워크스트림 묶기 | 조율 메시지 초안 |
| context | 인계 요청문 복사 | 무시 |
| hygiene | 선택 → 일괄 보관(두 번 클릭, 손실 경고) | 유지 |
| 검증 결과 | 근거 열기 | 반박 내용을 답 초안으로 |

**선택지 칩(규칙층):**
- `needs_action`의 "choose:/pick:/중 선택:" 뒤를 `/`·`,`·` or `로 나눈다.
- 칩을 누르면 그 문구를 복사하고 세션을 연다.
- 아티팩트 안에서 클립보드 쓰기가 막히면 선택 가능한 입력란으로 대신 보여 준다 [미확인].

**비서 채팅(샘플층 + 페이지 도구):**
- 읽기 도구: `inbox.list`, `card.get`, `ws.get`, `ledger.search`, `events.peek(session_id, ≤20, result만)`.
- 제안 도구: `propose(channel, target, draft)`. 제안은 실행 버튼이 달린 카드로만 그려진다. 모델이 직접 실행하지는 못한다.
- `sample`은 메모리가 없다 [문서]. 그래서 호출할 때마다 원장에서 카드와 결정을 다시 싣는다.

**아침 브리프:** 페이지를 열어야만 보이는 비서는 "놓치는" 문제를 되풀이한다. 그래서 브리프는 매니저가 써서 알린다.
- P1: 매니저가 깨어날 때 `brief/<day>`를 쓰고, 세션 도구 목록에 있는 `PushNotification`으로 알린다(F16).
- T1·T3 통과 뒤: 예약 작업으로 옮긴다.
- 콘솔: 같은 내용을 보여 준다. 클릭하면 U0를 다시 계산해 갱신한다.
- 내용: 결정 상위 5개(각각 추천 한 줄), 어제 완료와 검증 상태, 놓친 후속과 안 읽은 결과, 진척이 멈춘 세션, 정리 후보, 위험. 비용은 맨 끝에 참고로 한 줄만 둔다.
