# 작업공간 지도 (통합 과제, 일부 구현)

| 항목 | 내용 |
|---|---|
| 상태 | 컨테이너 측정(W1–W2의 휘발 판정)은 구현했다. 엔진은 fsmap이다(§3a, 콘솔 v12, `aok-atlas`). 나머지(파일 활동, GitHub·Drive 색인, 타임라인)는 제안이다 |
| 목표 | 세션마다의 작업과 맥락, 각 세션 클라우드 컨테이너의 파일, 공통 작업공간(GitHub, Google Drive, Artifact)을 **하나의 지도**로 관리한다. 의미 있는 시각화를 포함한다 |
| 판단 축 | 협업 효용이다. 최신본이 어디 있는지, 무엇이 아직 저장되지 않았는지, 누가 무엇을 바꿨는지, 누가 누구를 기다리는지를 본다. 비용은 참고 수치다 |

## 1. 이 지도가 답해야 하는 질문

| 장면 | 질문 | 지금의 어려움 |
|---|---|---|
| 이어 하기 | "이 작업의 최신본은 어디 있지? 레포, Drive, 아티팩트, 아니면 아직 컨테이너 안?" | 세션마다 저장 위치가 다르고 기록이 흩어져 있다 |
| 휘발 방지 | "이 세션이 만든 파일이 커밋·업로드됐나?" | 컨테이너는 유휴 뒤 회수된다. 푸시하지 않은 산출물은 사라진다 [문서: 실행 환경 안내]. 실제로 산출물을 컨테이너에만 둔 채 저장 위치 결정을 기다리는 세션이 있었다 [기록됨: 2026-10-30]. 문구 기반 1차 감지는 콘솔 IN24로 들어갔다 |
| 충돌 예방 | "두 세션이 같은 파일이나 같은 Drive 문서를 건드리나?" | v2 IN11은 같은 레포까지만 본다 |
| 출처 추적 | "Drive의 이 문서는 어느 세션이 왜 만들었나?" | 문서와 세션 사이의 연결이 없다 |
| 인계 | "새 세션에 무엇을 넘겨야 하나?" | 브랜치, PR, 문서, 아티팩트를 사람이 기억해서 모은다 |
| 협업 흐름 | "어디서 AI가 사람을 기다렸고, 어디서 사람이 AI를 기다렸나?" | 시간축 위에서 볼 수 없다 |

## 2. 모델

노드: **세션**(맥락 카드) · **워크스트림** · **레포/브랜치/PR** · **파일**(위치: container / repo / drive / artifact) · **Drive 문서·폴더** · **아티팩트**.

| 관계 | 의미 | 원천 |
|---|---|---|
| 세션 → works_on → 레포·브랜치 | 세션이 붙은 레포, 현재 브랜치, 결과 브랜치 | `session_context.sources`, `external_metadata.current_branches`, `session_context.outcomes[].git_repository.git_info.branches` |
| 세션 → touched → 파일 | 읽음·씀·고침과 시각 | `list_events`의 tool_use 입력. Write·Edit의 파일 경로와 Bash 명령(리다이렉트, `tee`, heredoc, `sed -i`, 빌드 산출물)을 함께 본다 |
| 세션 → produced → 아티팩트 | 세션이 만든 아티팩트 | `external_metadata.artifacts` |
| 브랜치 → has → PR, checks | 병합 상태와 CI | GitHub(`gh`) |
| 세션 → wrote → Drive 문서 | 업로드·수정 | Drive 커넥터 + 이벤트의 Drive 도구 호출 |
| 파일 → persisted_as → 커밋·Drive·아티팩트 | 휘발 여부 판정 | 위 관계들의 조인 |

## 3a. 엔진 결정: fsmap (2026-10-30)

**결정.** 컨테이너 측정 엔진으로 사용자의 Rust CLI fsmap(공개 레포 `d-j-lee/filesystemMap`)을 쓴다. 세션은 `fsmap scan`으로 자기 작업공간을 재고, `scripts/atlas_record.py`로 줄여 원장 `atlas/<session_id>`(`schemas/ledger.schema.json#/$defs/atlas`)에 올린다. 절차는 `.claude/skills/aok-atlas/SKILL.md`다.

| 후보 | 장점 | 단점 | 판단 |
|---|---|---|---|
| **fsmap 측정** | git 위생을 직접 잰다. fsmap은 저장소마다 미커밋, 앞선 커밋, stash, 업스트림 없거나 앞선 브랜치를 내고, 추적 안 된 파일은 따로 센다. fsmap이 놓치는 detached HEAD 커밋과 업스트림이 지워진 브랜치는 변환기가 git으로 대조해 메운다. 결정적이고 빠르다(클론 3개 0.19초). 출력에 파일 내용이 없다. 규모, 빌드 산출물, 발견, HTML 지도를 덤으로 준다. 사용자의 다른 세션이 만든 도구라 생태계가 하나로 이어진다 | 세션이 스스로 실행해야 한다. 빌드 1–3분(D22) | 채택 |
| 이벤트 경로 추출(F11) | 다른 세션을 깨우지 않고 매니저가 할 수 있다 | Bash로 쓴 파일을 놓친다. 커밋·푸시 여부는 알 수 없다 | 보완. 저장소 밖 파일과 측정하지 않은 세션에 쓴다 |
| git 명령을 Python으로 직접 부르기 | 의존성이 없다 | fsmap이 이미 한 일(신뢰할 수 없는 저장소에 대한 안전한 git 설정, 이름 바뀐 파일 처리)을 다시 해야 한다 | 기각 |

- **계약 고정.** fsmap은 고정 커밋으로 쓴다. CI `atlas` 잡이 그 커밋을 빌드해 실제 스캔으로 변환기와 스키마를 확인한다. 커밋을 올릴 때는 CI와 스킬의 값을 함께 바꾼다.
- **범위.** 루트 아래 git 저장소만 "로컬 전용"으로 센다. 스크래치패드나 `/tmp`의 낱개 파일, gitignore된 파일은 범위 밖이다. 그래서 측정이 깨끗한데 요약 문구가 컨테이너 산출물을 말하면, 콘솔은 항목을 낮은 우선순위로 남긴다.
- **빈틈.** 측정할 수 없었던 것(원격 대조 실패, git 오류, 분석 한도 초과, 저장소 없음)은 레코드 `coverage.gaps`에 남는다. 빈틈이 있으면 깨끗함의 근거로 쓰지 않는다.

## 4. 시각화

| 보기 | 형태 | 답하는 질문 |
|---|---|---|
| 워크스트림 지도 | 열 = 작업공간(레포·Drive 폴더·아티팩트), 행 = 워크스트림, 점 = 세션, 선 = 만듦·고침·읽음 | 무엇이 어디에 있고 무엇과 이어지나 |
| 협업 타임라인 | 세션별 스윔레인. 구간 색 = 공 보유(AI 작업 / 사람 대기). 표식 = 커밋, PR, 파일 쓰기, 업로드 | 어디서 누가 누구를 기다렸나 |
| 파일 활동 맵 | 경로 트리 × 세션. 같은 파일을 여러 세션이 고치면 강조(IN22 "같은 파일 동시 작업") | 충돌, 중복 작업 |
| 휘발 위험 목록 | 이벤트에 쓰기는 있는데 커밋·업로드·아티팩트가 없는 파일. 컨테이너 회수·보관 전에 경고하고, 일괄 보관 후보에서 뺀다 | 사라질 산출물 |
| 최신본 찾기 | 같은 이름·주제 문서의 위치들을 수정 시각순으로 | 어느 것이 최신인가 |

시각화는 콘솔 안에 인라인 SVG로 그린다. 노드가 많으면 cdnjs의 고정 버전 d3를 쓴다. 상세는 `artifact-diagramming`·`dataviz` 지침을 따른다.

## 5. 배치

- **콘솔:** 지도와 시각화, 커넥터로 바로 얻는 세션 메타데이터, 클릭 시 증분 이벤트를 맡는다.
- **매니저 세션:** GitHub·Drive 스냅숏을 만들어 원장 `atlas/*`에 쓴다(문서 256KB 한도 안에서 레포·폴더 단위로 쪼갠다). 이벤트 파일 활동은 서브에이전트로 정제한다.
- **원장(비공개):** 경로·제목·발췌만 둔다. 파일 내용은 두지 않는다. 공개 레포에는 스키마와 합성 픽스처만 둔다.

## 6. 단계

| 단계 | 범위 | 종료 조건 |
|---|---|---|
| W0 실측 | F11–F14 | 각 시험의 원시 결과 기록 |
| W1 메타 지도 | 세션 ↔ 레포·브랜치 ↔ 아티팩트(커넥터만). 원장 읽기 `admin`(v2 D15)이 먼저다 | 활성 세션 전부가 지도에 놓인다 |
| W2 파일 활동 | 휘발 위험은 fsmap 측정으로 구현했다(콘솔 인박스·작업공간 카드·타일). 남은 것: 이벤트에서 파일 경로 추출(Bash 포함, 저장소 밖 파일 보완), IN22 | 휘발: 측정한 세션의 로컬 전용 작업이 인박스와 카드에 보인다 [확인: 합성 사례 10건, 실측 1건]. 경로 추출: 수작업 대조 10건에서 누락 1건 이하 |
| W3 GitHub | 매니저 스냅숏(PR·checks·변경 파일) | 세션의 PR 주장과 GitHub 상태가 지도에서 한 번에 보인다 |
| W4 Drive | Drive 연결 뒤 지정 폴더 이하 색인, 세션 출처 연결 | 사용자가 지정한 폴더의 문서가 세션과 이어진다 |
| W5 타임라인 | 공 보유 스윔레인, 최신본 찾기 | 사용자 평가 |

| 시험 | 내용 |
|---|---|
| F11 | Write·Edit·NotebookEdit 이벤트에서 `file_path`를, Bash 명령에서 쓰기 대상을 얼마나 뽑을 수 있나. 서브에이전트 이벤트도 포함되나 |
| F12 | 콘솔(Artifact `mcp` 능력)에서 Drive·GitHub 커넥터를 부를 수 있나 |
