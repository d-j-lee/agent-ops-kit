# 작업공간 지도 (다음 통합 과제, 제안 초안)

| 항목 | 내용 |
|---|---|
| 상태 | 과제 정의와 실현성 초안. 관제탑 v2(`control-tower-v2.md`)의 결정을 받은 뒤 설계를 확정한다 |
| 목표 | 세션마다의 작업과 맥락, 각 세션 클라우드 컨테이너의 파일, 공통 작업공간(GitHub, Google Drive, Artifact)을 **하나의 지도**로 관리한다. 의미 있는 시각화를 포함한다 |
| 판단 축 | 협업 효용이다. 최신본이 어디 있는지, 무엇이 아직 저장되지 않았는지, 누가 무엇을 바꿨는지, 누가 누구를 기다리는지를 본다. 비용은 참고 수치다 |

## 1. 이 지도가 답해야 하는 질문

| 장면 | 질문 | 지금의 어려움 |
|---|---|---|
| 이어 하기 | "이 작업의 최신본은 어디 있지? 레포, Drive, 아티팩트, 아니면 아직 컨테이너 안?" | 세션마다 저장 위치가 다르고 기록이 흩어져 있다 |
| 휘발 방지 | "이 세션이 만든 파일이 커밋·업로드됐나?" | 컨테이너는 유휴 뒤 회수된다. 푸시하지 않은 산출물은 사라진다 [문서: 실행 환경 안내] |
| 충돌 예방 | "두 세션이 같은 파일이나 같은 Drive 문서를 건드리나?" | v2 H11은 같은 레포까지만 본다 |
| 출처 추적 | "Drive의 이 문서는 어느 세션이 왜 만들었나?" | 문서와 세션 사이의 연결이 없다 |
| 인계 | "새 세션에 무엇을 넘겨야 하나?" | 브랜치, PR, 문서, 아티팩트를 사람이 기억해서 모은다 |
| 협업 흐름 | "어디서 AI가 사람을 기다렸고, 어디서 사람이 AI를 기다렸나?" | 시간축 위에서 볼 수 없다 |

## 2. 모델

노드: **세션**(맥락 카드) · **워크스트림** · **레포/브랜치/PR** · **파일**(위치: container / repo / drive / artifact) · **Drive 문서·폴더** · **아티팩트**.

| 관계 | 의미 | 원천 |
|---|---|---|
| 세션 → works_on → 레포·브랜치 | 세션이 붙은 레포와 현재 브랜치 | `session_context.sources`, `external_metadata.current_branches` |
| 세션 → touched → 파일 | 읽음·씀·고침과 시각 | `list_events`의 tool_use 입력(파일 경로, 명령) |
| 세션 → produced → 아티팩트 | 세션이 만든 아티팩트 | `external_metadata.artifacts` |
| 브랜치 → has → PR, checks | 병합 상태와 CI | GitHub(`gh`) |
| 세션 → wrote → Drive 문서 | 업로드·수정 | Drive 커넥터 + 이벤트의 Drive 도구 호출 |
| 파일 → persisted_as → 커밋·Drive·아티팩트 | 휘발 여부 판정 | 위 관계들의 조인 |

## 3. 원천별 실현성 (2026-10-21 실측)

| 원천 | 얻는 것 | 수단 | 상태 |
|---|---|---|---|
| `list_sessions` | 레포, 현재 브랜치, 아티팩트 목록, 작업 요약, 공 보유 | 콘솔 커넥터 | 필드 존재 [확인: 3건 조회] |
| `list_events` | tool_use 입력(명령, 파일 경로), 결과 | 콘솔(R1 증분) 또는 매니저(`harvest_events.py`) | tool_use 입력이 이벤트에 들어 있다 [확인: 자식 세션 1건]. Write·Edit의 `file_path`를 뽑을 수 있다는 것은 같은 구조에서 [추론] |
| 세션 컨테이너 파일시스템 | 실제 파일 내용 | 다른 세션 컨테이너를 직접 읽는 도구는 없다 [추론: 도구 목록에 없음] | 간접 수단만 있다. 이벤트의 경로·내용, 푸시된 브랜치, 업로드된 산출물. 그래서 "휘발 위험" 표시가 핵심 가치다 |
| GitHub | 브랜치, 커밋, PR, checks, 변경 파일 | 매니저 컨테이너의 `gh`(프록시) → 원장 스냅숏 | 이 세션에서 `gh`가 동작한다 [확인: PR 생성은 REST로]. 콘솔에서 직접 조회하는 커넥터는 [미확인] |
| Google Drive | 문서·폴더, 수정자·시각, 경로(`claude5/` 이하) | claude.ai Drive 커넥터 | 이 세션의 플러그인 커넥터는 인증 단계에서 거부됐다 [확인]. 연결은 claude.ai 커넥터 설정에서 하고 새 세션부터 적용된다 [문서] |
| Artifact | 세션별 산출물, 버전 | `external_metadata.artifacts`, Artifact 도구 | [확인] |

## 4. 시각화

| 보기 | 형태 | 답하는 질문 |
|---|---|---|
| 워크스트림 지도 | 열 = 작업공간(레포·Drive 폴더·아티팩트), 행 = 워크스트림, 점 = 세션, 선 = 만듦·고침·읽음 | 무엇이 어디에 있고 무엇과 이어지나 |
| 협업 타임라인 | 세션별 스윔레인. 구간 색 = 공 보유(AI 작업 / 사람 대기). 표식 = 커밋, PR, 파일 쓰기, 업로드 | 어디서 누가 누구를 기다렸나 |
| 파일 활동 맵 | 경로 트리 × 세션. 같은 파일을 여러 세션이 고치면 강조(H22 "같은 파일 동시 작업") | 충돌, 중복 작업 |
| 휘발 위험 목록 | 이벤트에 쓰기는 있는데 커밋·업로드·아티팩트가 없는 파일. 컨테이너 회수 전에 경고 | 사라질 산출물 |
| 최신본 찾기 | 같은 이름·주제 문서의 위치들을 수정 시각순으로 | 어느 것이 최신인가 |

시각화는 콘솔 안에 인라인 SVG로 그린다. 노드가 많으면 cdnjs의 고정 버전 d3를 쓴다. 상세는 `artifact-diagramming`·`dataviz` 지침을 따른다.

## 5. 배치

- **콘솔:** 지도와 시각화, 커넥터로 바로 얻는 세션 메타데이터, 클릭 시 증분 이벤트를 맡는다.
- **매니저 세션:** GitHub·Drive 스냅숏을 만들어 원장 `atlas/*`에 쓴다(문서 256KB 한도 안에서 레포·폴더 단위로 쪼갠다). 이벤트 파일 활동은 서브에이전트로 정제한다.
- **원장(비공개):** 경로·제목·발췌만 둔다. 파일 내용은 두지 않는다. 공개 레포에는 스키마와 합성 픽스처만 둔다.

## 6. 단계

| 단계 | 범위 | 종료 조건 |
|---|---|---|
| A0 실측 | F11–F14 | 각 시험의 원시 결과 기록 |
| A1 메타 지도 | 세션 ↔ 레포·브랜치 ↔ 아티팩트(커넥터만) | 활성 세션 전부가 지도에 놓인다 |
| A2 파일 활동 | 이벤트에서 파일 경로 추출, 휘발 위험, H22 | 수작업 대조 10건에서 경로 누락 1건 이하 |
| A3 GitHub | 매니저 스냅숏(PR·checks·변경 파일) | 세션의 PR 주장과 GitHub 상태가 지도에서 한 번에 보인다 |
| A4 Drive | Drive 연결 뒤 `claude5/` 이하 색인, 세션 출처 연결 | 사용자가 지정한 폴더의 문서가 세션과 이어진다 |
| A5 타임라인 | 공 보유 스윔레인, 최신본 찾기 | 사용자 평가 |

| 시험 | 내용 |
|---|---|
| F11 | Write·Edit·NotebookEdit 이벤트에서 `file_path`를 안정적으로 뽑을 수 있나. 서브에이전트 이벤트도 포함되나 |
| F12 | 콘솔(Artifact `mcp` 능력)에서 Drive·GitHub 커넥터를 부를 수 있나 |
| F13 | 사용자 소유 레포 전체의 브랜치·PR 스냅숏에 걸리는 시간과 원장 크기 |
| F14 | 컨테이너 회수 뒤 이벤트만으로 파일 내용을 어디까지 복원할 수 있나 |
