AOK 안내서 · 기능 ⑧ · D26

작업 레포 하네스

AOK의 다른 기능은 허브와 세션의 층에서 돕니다. ⑧은 자식이 실제로 코드를 고치는 레포 안에 둡니다. 깨진 코드로 끝난 턴을 사람이 PR에서 처음 보는 일을 줄이는 것이 목적입니다.

왜

에이전트는 "고쳤다"고 말한 뒤에 턴을 끝냅니다. 그 말이 맞는지는 누군가 컴파일하고 시험을 돌려야 압니다. 사람이 PR에서 그 일을 하면 늦고, 자식이 스스로 하면 빼먹거나 검사를 약하게 만들어 통과시킬 수 있습니다 추론. ⑧은 그 일을 레포의 훅으로 옮깁니다. 편집 직후, 턴 종료, 푸시 직전에 같은 게이트가 돌고, 사람과 CI도 같은 명령을 씁니다.

⑦과 나눠 맡습니다. ⑦은 "바꾸기 전에 되던 것이 바꾼 뒤에도 되는가"를 기준과 비교로 고정합니다. ⑧은 "지금 이 트리가 레포의 검사를 통과하는가"를 매 턴 봅니다. 하네스 자신의 시험이 공허하지 않은지는 ⑦의 도구로 확인합니다.

언제 무엇이 도나

순간훅하는 일
세션 시작SessionStart새 세션에서만 기준(HEAD, 이미 바뀐 파일의 해시)을 기록하고, 어댑터와 실제 도구 판을 알린다. 하네스를 쓸 수 없으면 "OFF"와 이유를 사용자에게 보인다
편집 직후PostToolUse어댑터가 맡는 파일이면 그 파일에 편집 검사(Python: 컴파일·ruff, Rust: cargo check). 실패는 Claude에게 돌아간다
턴 종료Stop이 세션이 트리를 바꿨고 이미 통과한 트리가 아니면 quick 게이트. 실패와 실행 불가 모두 막는다. 3번 연속 막히면 놓아 주고 "통과하지 않았다"고 알린다. 통과하면 이 세션이 약하게 만든 검사와 하네스 자체의 변경을 보고한다
사용자 입력UserPromptSubmit막힌 횟수를 0으로
게시 명령PreToolUsegit push·gh pr create를 막는다: 훅을 끄는 옵션, 이 세션의 하네스·설정 변경, 커밋하지 않은 변경, quick 게이트 실패나 실행 불가

사람·에이전트·CI: python3 -I .aok/harness/aok_harness.py verify --mode quick|full [--json]. 종료 0 통과 · 1 실패 · 2 실행 불가. 훅의 JSON 필드와 시간 제한 기본값은 Claude Code 문서를 따릅니다(명령 훅 {{fig:hook.timeout}}) {{grade:C-hook-doc}}.

설계의 축

판정받는 쪽이 기준을 못 바꾼다

  • 게이트 정의는 세션이 시작된 커밋의 .aok/harness.json에서 읽는다. 작업 트리에서 바꾼 정의는 쓰이지 않고 보고된다
  • .aok/·.claude/settings*.json을 바꾼 세션의 푸시는 막고 사람에게 넘긴다
  • CI는 기준 브랜치의 정의로 돈다(verify --base origin/main)

닫힌 실패, 그리고 출구

  • 필수 도구가 없거나, 단계가 시간을 넘기거나, 설정을 읽을 수 없거나, 하네스가 죽으면 통과로 치지 않는다
  • 선택 도구가 없으면 건너뛰되 세션에 한 번 알린다
  • 3번 막히면 놓아 준다. 막힌 자식이 예산을 태우며 맴돌지 않고 AOK/1 blocked로 보고하게 한다
  • 세션이 아무것도 바꾸지 않았으면 판정하지 않는다. 남이 남긴 실패는 그 세션의 것이 아니다

코어는 언어를 모릅니다. 지문(HEAD + 바뀐 파일 내용 + 게이트 정의), 기준, 막힘 횟수, 약화 보고, 푸시 판단이 코어의 일이고, 무엇을 돌릴지는 어댑터(데이터 파일)가 정합니다. 어댑터를 둘(Python, Rust) 둔 것은 이 분리가 실제로 언어와 무관한지 시험으로 보이기 위해서입니다. 새 언어는 harness/adapters/<이름>.json 하나로 더합니다.

검증에서 나온 것라운드마다 게이트 우회와 공허한 훅 시험이 나왔다 {{grade:C-harness-log}}그 부류를 수락 기준으로 받아 시험과 변이로 고정했다

1회차의 Rust 판 구성과 겪은 일은 Rust 트랙 페이지의 하네스 절에 있습니다.

들이기

  1. 1

    계획을 보인다

    python3 -I harness/aok_harness.py install --repo <작업 레포> --adapter python. --yes 없이는 아무것도 쓰지 않고 계획만 보입니다.

    허브
  2. 2

    사람이 확인한다

    레포의 .claude/settings.json을 바꾸는 일이라 S4입니다. 확인을 받은 뒤 --yes로 다시 돌립니다. 기존 설정은 보존되고 두 번 돌려도 훅이 겹치지 않습니다.

    사람
  3. 3

    PR로 올린다

    .aok/와 .claude/를 커밋합니다. 훅은 다음 세션부터 돕니다. 첫 세션의 맥락이 [aok-harness] adapter …(Rust를 fsmap에 맡기면 [harness] fsmap …)로 시작하는지 봅니다.

    허브 → 사람
  4. 4

    CI에 기준 정의 잡

    기존 단계는 그대로 두고 verify --mode full --base origin/main 잡을 더합니다. PR이 고친 정의가 아니라 기준 브랜치의 정의로 판정합니다.

    허브

한계

가드레일이지 보안 경계가 아니다에이전트는 코어 파일, 상태 디렉터리, 로컬 설정을 고칠 수 있습니다. ask 규칙과 푸시 거부가 그런 변경을 사람 앞에 드러내고, 깨끗한 체크아웃에서 기준 정의로 도는 CI가 정본 게이트입니다.
게시 명령 읽기는 휴리스틱git … push와 gh pr create를 정규식으로 찾습니다. 별칭, 스크립트 파일, API·MCP 도구로 하는 게시는 보지 못합니다. git 자체의 pre-push 훅으로 보는 방식은 fsmap(1회차)에 있습니다.
원격 자식에서 도는지레포의 훅은 레포 하나로 연 클라우드 세션에서 적용된다고 문서에 적혀 있습니다 문서. 원격 자식 세션에서 실제로 도는지는 아직 시험하지 않았습니다 미확인. 그 전에는 사람이 여는 세션에 먼저 씁니다.
백그라운드 작업Stop 입력에 background_tasks가 있으면 게이트를 미룹니다. 이 필드는 공식 문서에서 찾지 못했고 fsmap이 실제 세션 기록에서 본 것입니다 기록됨.
레포 코드를 실행한다시험과 빌드 스크립트가 돕니다. 믿지 않는 레포에는 켜지 않습니다.

자기 시험

훅 다섯 개, verify, install, 두 어댑터의 동작마다 시험이 있고 {{fig:h8.tests}}가 통과합니다 {{grade:C-h8-tests}}. Rust 위임은 가짜 실행 파일에 더해 고정 커밋으로 빌드한 fsmap으로도 시험합니다 {{grade:C-h8-fsmap}}. 기준을 작업 트리에서 읽게 하기, 실행 불가를 통과로 치기, 첫 커밋을 세지 않기, 푸시 거부를 끄기처럼 장치를 하나씩 끈 {{fig:h8.muts}}마다 지정한 시험이 실패합니다 {{grade:C-h8-muts}}. CI가 별도 잡으로 돌립니다. 변이 목록: {{doc:tests/mutations/harness.json}}
