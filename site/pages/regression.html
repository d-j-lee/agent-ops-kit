왜 따로 두나

① 블라인드 재현 대조는 판단이 필요한 주장을 독립된 눈으로 봅니다. sha 비교나 테스트 통과 같은 결정적 비교는 "스크립트로 충분"하다며 범위 밖에 두었습니다. 그런데 그 스크립트도 스스로 속습니다. 출발점 세션에서 아래의 일이 실제로 일어났고, 여러 건은 독립 검증자가 잡기 전까지 작성자가 알아채지 못했습니다 기록됨.

그래서 ⑦은 결정적 비교에 런북과 도구를 둡니다. ④ 리뷰 루프의 reviewer가 "고쳤다"를 보면, ⑦은 "깨지지 않았다"를 봅니다. 둘은 서로를 대신하지 않습니다 추론. ①과도 나눠 맡습니다. 비교 자체는 ⑦이 기계로 하고, 그 비교가 무엇을 증명하는지(투영이 주장만큼 넓은가, 시나리오가 대표적인가)는 ①이 판단합니다.

질문기능판정 방식
다른 눈으로 봐도 같은가① L1 블라인드 + 판정자독립 판단, 기계 대조
어떻게 하면 깨지는가① L0, ④ reviewer실험으로 재현한 것만 채택
깨끗한 곳에서 문서대로 되는가③ 클린룸글자 그대로 실행
고친 뒤에도 전에 되던 것이 되는가⑦ 회귀 고정고정된 기준 + 자동 반복 + 공허함 방지

회귀검증이 스스로 속는 경우

빈 출력끼리 비교측정 스크립트가 같은 세션 ID를 재사용해, work-atlas 편집 훅이 두 번째 실행부터 아무것도 내지 않았는데도 "동일"을 찍었습니다. 같은 ID로 다시 돌리면 출력이 {{fig:trap.empty}}가 됩니다 {{grade:C-trap-empty}}. 비교 전에 출력이 비어 있지 않은지 단언하고, 상태를 기억하는 도구에는 실행마다 새 키를 줍니다.
비교한 범위보다 넓은 주장docbench diff 이식을 줄 목록만 비교하고 "화면이 같다"고 썼습니다. 낱말 강조까지 같은 것은 {{fig:db.highlight}}였습니다. 무작위 입력에서는 {{fig:db.fuzz}}가 같았습니다 {{grade:C-db-fuzz}}. 무엇을 비교했는지(투영) 보고에 적고, 손으로 고른 사례에 무작위 입력을 더합니다.
비결정성을 고정하지 않음{{claim:C-trap-asof}} {{grade:C-trap-asof}} 기준 시각(--as-of)을 주면 같아집니다. 시각, 난수 시드, 세션 상태를 고정해야 "바이트 동일"을 비교할 수 있습니다.
의미가 미묘하게 다른 대체 구현표준 json을 orjson으로 바꾸자 현재 데이터는 같았지만 NaN, 아주 큰 수, 깊은 중첩 같은 입력에서 동작이 달라졌습니다. 그 판도 기존 테스트 {{fig:wa.tests}}를 모두 통과했습니다 기록됨. 테스트가 다루지 않는 입력이었기 때문입니다. 경계 입력표를 만들어 원본과 대조합니다.
수치 이식의 경계Rust로 옮긴 질의가 반올림 경계에서 Python과 달랐습니다. 실수 파싱이 1 ULP 어긋나 경계 값 {{fig:sim.ulp}}에서 결과가 갈렸고, 고친 뒤 0개가 됐습니다 {{grade:C-sim-ulp}}. 반올림 방식과 실수 파싱까지 맞추고, 일부러 만든 경계 값으로 비교합니다.
측정 잡음같은 훅의 절대 중앙값이 날마다 {{fig:wa.abs}}로 달랐습니다. 비율은 편집 훅 {{fig:wa.edit}}처럼 몇 %p 안에서 유지됐고, 같은 원본끼리 잰 A/A는 {{fig:wa.aa}}였습니다. 번갈아 여러 번 돌려 중앙값을 내고, A/A로 잡음 바닥을 알고, 한 번의 측정이 아니라 측정 간 범위를 보고합니다.
공허한 테스트수정마다 만든 회귀 테스트 중 {{fig:vacuous.total}}가 보호 장치를 지워도 통과했습니다 기록됨. 보호하려는 코드를 바꾼 변형에서 테스트가 실패하는지 봅니다. 문법이 깨진 변이나 시간 초과는 "잡았다"로 세지 않습니다.
실패를 "결과 없음"으로 읽음잘못된 경로를 주자 비교 스크립트가 "찾은 것 없음"으로 보고했습니다 기록됨. 도구 실패는 판정이 아니라 실행 불가로 멈추게 합니다.
⑦ 도구 자신이 기능의 첫 판에서 비교기는 서로 다른 잘못된 바이트, 공백뿐인 출력, --allow-fail에서의 종료 코드 차이를 "같다"고 볼 수 있었고, 시험은 문서에 적은 장치 다수를 지키지 못했습니다. ① T2 검증이 찾았습니다({{fig:pr4.only}} 중 일부) {{grade:C-brd-pr4}}. 지금은 변이마다 그것을 잡을 시험 이름을 붙여 CI가 확인합니다.

두 도구

둘 다 표준 라이브러리만 쓰고 python3 -I로 돕니다. 위의 함정을 그대로 시험 사례로 만들었습니다.

scripts/diffcheck.py — 전후 비교

  • 같은 입력을 기준·후보 명령에 넣어 종료 코드와 stdout을 바이트로 비교한다(--stderr면 stderr도). 무엇을 비교했는지 보고에 남는다
  • 빈 출력(공백뿐이거나 정규화 뒤 <N>만 남은 것 포함), 0이 아닌 종료, 시간 초과는 실패. --allow-fail이어도 종료 코드는 비교한다
  • --determinism은 각 쪽을 두 번 돌려 종료 코드·출력이 같은지 본다(A/A)
  • --normalize는 무엇을 몇 번 바꿨는지 보고에 남긴다
  • 명령 인자와 입력 파일의 {nonce}는 실행마다 새 토큰. --same-nonce는 한 쌍의 양쪽에 같은 새 토큰
  • --timing N은 기준과 후보를 번갈아 돌린다. 측정 중 실패도 실패
  • 명령을 실행할 수 없으면 판정 대신 종료 코드 2

scripts/vacuity_check.py — 공허한 테스트 검사

  • 레포를 임시 디렉터리에 복사하고, 변이는 사본 안에만 쓴다. 심볼릭 링크로 사본 밖을 가리키는 대상은 거부한다
  • 바꾸지 않은 사본에서 테스트가 통과해야 한다(기준)
  • 변이마다 새 사본에 적용해 테스트가 실패해야 한다(guarded). expect를 주면 그 글이 실패 출력에 있어야 한다
  • 변이는 정확히 한 곳에 맞아야 한다. 컴파일되지 않는 .py 변이는 invalid, 시간 초과는 timeout이고 통과가 아니다
  • --jobs N으로 변이를 동시에 돌린다

절차

  1. 1

    기준을 고정한다

    시각·시드·세션 상태를 옵션으로 고정하고 기준 커밋 sha를 적는다. 양쪽이 빌드 디렉터리·캐시를 공유하지 않게 한다. 기준이 없으면 통과가 아니라 비교 불가다. 무엇을 비교하는지(투영)를 한 줄로 정한다.

    작성자
  2. 2

    실패 테스트 먼저

    버그 수정이면 재현 테스트의 실패 출력을 보존하고, 고친 뒤 통과를 본다(FAIL_TO_PASS).

    작성자
  3. 3

    전체 테스트

    고친 파일의 테스트만이 아니라 전부(PASS_TO_PASS). 선택 의존성이 있으면 있을 때와 없을 때 둘 다.

    작성자 · CI
  4. 4

    음성 대조: 공허함 검사

    새 테스트와 보호 장치마다 vacuity_check. 변이마다 잡아야 할 시험 이름을 expect로. vacuous가 나오면 테스트를 고친다.

    작성자 · CI
  5. 5

    전후 비교와 양성 대조

    diffcheck --determinism으로 같은 입력의 결과를 비교한다(A/A 포함). 고른 사례에 무작위 입력을 더하고, 알려진 차이를 넣은 후보가 differs로 나오는지 한 번 본다. 성능은 기준끼리 잰 잡음 바닥과 함께 --timing으로 번갈아 잰다.

    작성자
  6. 6

    기록

    PR 코멘트에 두 도구의 요약을 남긴다. 주장은 claim 형식으로, [확인]의 근거는 위 명령 그대로.

    작성자 → reviewer

이 키트의 자기 시험

⑦의 도구와 이 안내서의 빌드가 공허하지 않은지도 ⑦로 봅니다. 문서에 적은 보호 장치(빈 출력 검사, 바이트 비교, 종료 코드 비교, 결정성 검사, 번갈아 측정, {nonce} 치환, 심볼릭 링크 거부, 문법 검사, 레지스트리 규칙, 수치 규칙, 로그 발췌 대조, 공개 레포 검사 등)를 하나씩 끈 {{fig:self.muts}}마다, 그 변이를 잡도록 지정한 시험이 실패합니다 {{grade:C-self-muts}}. CI가 같은 검사를 PR마다 돌립니다. 변이 목록: {{doc:tests/mutations/diffcheck.json}}, {{doc:tests/mutations/vacuity_check.json}}, {{doc:tests/mutations/build_site.json}}

처음부터 이랬던 것은 아닙니다. 첫 판에서는 손으로 고른 변이 7개만 시험했고, 독립 검증자가 추가로 넣은 변이 대부분에서 시험이 통과해 버렸습니다. 고쳐 가는 중에도 이 검사가 새로 쓴 시험 하나의 빈틈(공백뿐인 출력 검사를 꺼도 다른 검사가 같은 판정을 내서 통과)을 잡았습니다 기록됨.

근거
