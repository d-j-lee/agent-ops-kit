왜 따로 두나

① 블라인드 재현 대조는 판단이 필요한 주장을 독립된 눈으로 봅니다. sha 비교나 테스트 통과 같은 결정적 비교는 "스크립트로 충분"하다며 범위 밖에 둡니다. 그런데 그 스크립트도 스스로 속습니다. 출발점 세션에서 아래의 일이 실제로 일어났고, 여러 건은 독립 검증자가 잡기 전까지 작성자가 알아채지 못했습니다 기록됨.

그래서 ⑦은 결정적 비교에 런북과 도구를 둡니다. ④ 리뷰 루프의 reviewer가 "고쳤다"를 보면, ⑦은 "깨지지 않았다"를 봅니다. 둘은 서로를 대신하지 않습니다 추론.

질문기능판정 방식
다른 눈으로 봐도 같은가① L1 블라인드 + 판정자독립 판단, 기계 대조
어떻게 하면 깨지는가① L0, ④ reviewer실험으로 재현한 것만 채택
깨끗한 곳에서 문서대로 되는가③ 클린룸글자 그대로 실행
고친 뒤에도 전에 되던 것이 되는가⑦ 회귀 고정고정된 기준 + 자동 반복 + 공허함 방지

회귀검증이 스스로 속는 경우

빈 출력끼리 비교측정 스크립트가 같은 세션 ID를 재사용해, work-atlas 편집 훅이 두 번째 실행부터 아무것도 내지 않았는데도 "동일"을 찍었습니다. 같은 ID로 두 번 돌리면 출력이 {{fig:trap.empty}}가 됩니다 확인. 비교 전에 출력이 비어 있지 않은지 단언하고, 상태를 기억하는 도구에는 실행마다 새 키를 줍니다.
비교한 범위보다 넓은 주장docbench diff 이식을 줄 목록만 비교하고 "화면이 같다"고 썼습니다. 낱말 강조까지 같은 것은 {{fig:db.highlight}}였습니다. 무작위 입력 4,000쌍에서는 {{fig:db.fuzz}}가 같았습니다 확인. 무엇을 비교했는지(투영) 보고에 적고, 손으로 고른 사례에 무작위 입력을 더합니다.
비결정성을 고정하지 않음{{claim:C-trap-asof}} 확인 기준 시각(--as-of)을 주면 같아집니다. 시각, 난수 시드, 세션 상태를 고정해야 "바이트 동일"을 비교할 수 있습니다.
의미가 미묘하게 다른 대체 구현표준 json을 orjson으로 바꾸자 현재 데이터는 같았지만 NaN, 아주 큰 수, 깊은 중첩 같은 입력에서 동작이 달라졌습니다. 그 판도 기존 테스트 {{fig:wa.tests}}를 모두 통과했습니다 기록됨. 테스트가 다루지 않는 입력이었기 때문입니다. 경계 입력표를 만들어 원본과 대조합니다.
수치 이식의 경계Rust로 옮긴 질의가 반올림 경계에서 Python과 달랐습니다. 실수 파싱이 1 ULP 어긋나 경계 값 {{fig:sim.ulp}}에서 결과가 갈렸고, 고친 뒤 0개가 됐습니다 확인. 반올림 방식과 실수 파싱까지 맞추고, 일부러 만든 경계 값으로 비교합니다.
측정 잡음원본과 패치를 몰아서 재면 실행마다 비율이 {{fig:wa.range}}로 흔들렸습니다 확인. 번갈아 여러 번 돌려 중앙값을 내고, 한 번의 측정이 아니라 측정 간 범위를 보고합니다.
공허한 테스트수정마다 만든 회귀 테스트 중 {{fig:vacuous.total}}가 보호 장치를 지워도 통과했습니다 기록됨. 보호하려는 코드를 바꾼 변형에서 테스트가 실패하는지 봅니다.
실패를 "결과 없음"으로 읽음잘못된 경로를 주자 비교 스크립트가 "찾은 것 없음"으로 보고했습니다 기록됨. 도구 실패는 실패로 멈추게 합니다.

두 도구

둘 다 표준 라이브러리만 쓰고 python3 -I로 돕니다. 위의 함정을 그대로 시험 사례로 만들었습니다.

scripts/diffcheck.py — 전후 비교

  • 같은 입력을 기준·후보 명령에 넣어 출력을 비교한다
  • 빈 출력, 0이 아닌 종료 코드, 실행마다 다른 출력(--determinism)은 실패
  • --normalize는 무엇을 몇 번 바꿨는지 보고에 남긴다
  • 명령 인자와 입력 파일의 {nonce}는 실행마다 새 토큰
  • --timing N은 기준과 후보를 번갈아 돌린다

scripts/vacuity_check.py — 공허한 테스트 검사

  • 레포를 임시 디렉터리에 복사한다. 원본은 건드리지 않는다
  • 바꾸지 않은 사본에서 테스트가 통과해야 한다(기준)
  • 변이마다 새 사본에 적용해 테스트가 실패해야 한다(guarded)
  • 변이는 정확히 한 곳에 맞아야 한다. 오타로 아무것도 안 바꾸고 통과하는 일을 막는다

절차

  1. 1

    기준을 고정한다

    시각·시드·세션 상태를 옵션으로 고정하고 기준 커밋 sha를 적는다. 무엇을 비교하는지(투영)를 한 줄로 정한다.

    작성자
  2. 2

    실패 테스트 먼저

    버그 수정이면 재현 테스트의 실패 출력을 보존하고, 고친 뒤 통과를 본다(FAIL_TO_PASS).

    작성자
  3. 3

    전체 테스트

    고친 파일의 테스트만이 아니라 전부(PASS_TO_PASS). 선택 의존성이 있으면 있을 때와 없을 때 둘 다.

    작성자 · CI
  4. 4

    공허함 검사

    새 테스트와 보호 장치마다 vacuity_check. vacuous가 나오면 테스트를 고친다.

    작성자 · CI
  5. 5

    전후 비교

    diffcheck로 같은 입력의 출력을 비교한다. 고른 사례에 무작위 입력을 더한다. 성능은 --timing으로 번갈아 잰다.

    작성자
  6. 6

    기록

    PR 코멘트에 두 도구의 요약을 남긴다. 주장은 claim 형식으로, [확인]의 근거는 위 명령 그대로.

    작성자 → reviewer

이 키트의 자기 시험

⑦의 도구 시험이 공허하지 않은지도 ⑦로 봅니다. 빈 출력 검사를 끄거나, 결정성 검사를 끄거나, {nonce} 치환을 멈추거나, "정확히 한 곳" 규칙을 지우는 식으로 보호 장치 하나씩을 끈 {{fig:self.muts}}를 넣으면 시험이 모두 실패합니다 확인. CI가 같은 검사를 PR마다 돌립니다.
