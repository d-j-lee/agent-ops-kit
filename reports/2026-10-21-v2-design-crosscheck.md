# 관제탑 v2 설계 대조 기록 (2026-10-21)

결과는 `docs/proposals/control-tower-v2.md`에 반영했다. 이 문서는 어떻게 합쳤는지만 남긴다.

번호는 당시 표기다. 휴리스틱 H01–H21은 지금 IN01–IN21, 갱신 R0–R3은 U0–U3, 층 D/S/M/R은 규칙층·샘플층·매니저층·원격층이다.

## 방법

- 허브가 설계안 A를 썼다.
- 같은 시각, A를 보지 않은 새 서브에이전트(블라인드 설계자)에게 같은 목표와 비공개 스냅숏(세션 35개 메타데이터)을 주고 설계안 B를 받았다. B의 규모는 약 2,000단어, 241k 토큰, 17.4분이었다 [확인: 작업 완료 알림].
- 대조는 허브가 했다. 사실이 엇갈린 곳은 말로 정하지 않고 원자료를 다시 조회해 정했다.

## B에서 채택한 것

| 항목 | 이유 |
|---|---|
| 지출 비중(사람 세션이 99% 이상) | 관점 전환의 가장 강한 근거. 허브가 스냅숏으로 다시 계산해 같은 값을 얻었다 [도출] |
| 병합 대기를 결정 대기와 분리(H04) | 행동이 다르다(버튼 한 번). MVP-1.1에 구현했다 |
| 설정·권한 변경 요청 표시(H16) | S4·S8을 화면에서 지키게 한다. MVP-1.1에 구현했다 |
| ~~우선순위에 비용 가산~~ | 상한을 두어 구현했다가, 사용자 피드백("판단 축은 협업 효용이고 비용은 참고 수치")으로 비용 가산과 "비용 핫스팟" 항목을 모두 뺐다. 대기 시간 가산만 남겼다 |
| 사람/자식 출처 표시 | 같은 신호라도 개입 수단이 다르다. 구현했다 |
| 워크스트림(`ws`), 비슷한 제목 감지(H12) | 중간관리자의 포트폴리오 관점 |
| 개입 결과 측정(`interventions.outcome`)과 기각 사유 | 휴리스틱을 스스로 교정하는 근거. 조정은 제안만 한다 |
| 결정 기억(H18) | 같은 질문이 반복될 때 이전 결정을 내민다 |
| 서명·커서 기반 증분 갱신 | 대화 기록 재독을 막는다. v1 시험 번호(T1–T8)와 겹치지 않게 R0–R3으로 이름을 바꿨다 |
| 사다리 V1 "외부 원천"(PR·checks·sha 대조), V2 "블라인드 추출", V5 "사람" | A의 사다리보다 싸고 독립적인 단을 앞에 둔다 |
| `sample` 출력은 JSON 스키마로, 실행은 `propose` 카드로만 | 주입 대책이 구체적이다 |
| 단계별 수치 종료 조건 | 확정 여부를 측정할 수 있다 |
| 원장 읽기 `view` 위험 | A가 놓친 프라이버시 위험이다. D15로 올렸다 |
| 자율 수준 이름 A0–A3 | BRD의 L0–L2와 겹치지 않는다 |

## A에서 유지한 것

- 인박스 항목은 매번 계산하고 사람의 처리 상태(`inbox_state`)만 저장한다. 이미 구현돼 있고 쓰기가 적다. B는 항목 자체를 저장하는 안이었다.
- 주문서(`requests`). B의 "인박스 승인 + 초인종"과 같은 생각인데, 매니저가 처리 상태를 남길 자리가 필요하다.
- 검증 결과는 새 컬렉션(`reviews`)을 만들지 않고 v1 `verifications`를 확장한다. B와 같은 결론이다.

## 반박되어 버린 것

| B의 주장 | 다시 본 결과 |
|---|---|
| 권한 대기 세션 3건이 COMPLETED로 보인다(버킷 불일치) | 세 건 모두 `session_status=ARCHIVED`였다. 보관하면 버킷이 COMPLETED로 바뀌고 예전 `needs_action`이 남을 뿐이다 [확인: 원본 list_sessions 응답]. 원인은 허브가 B에게 준 요약 스냅숏에서 `session_status`를 뺀 것이다. 패킷을 만들 때 상태 필드를 빼지 않는다 |

## 등급을 낮춰 옮긴 것

- B가 셌다고 한 수치(첫날 주 레인 9건 + 묶음 16건, 완료형 주장 7세션)는 다른 에이전트의 보고라 [기록됨]이다. 허브가 다시 잰 값(하네스 21건·긴급 4건, 정규식 6–7세션)으로 바꿨다.
- 이벤트 페이지 크기 "수십–수백 KB"는 이 레포에 측정 기록이 없다. [미확인]으로 두고 F4로 잰다.

## 사용자 피드백 반영 (같은 날)

- 판단 축을 비용에서 협업 효용으로 바꿨다. 공 보유, 사람 응답 지연, 놓친 후속, 검증된 주장, 개입 효과, 결정 재사용을 쓴다(제안서 §2a).
- 콘솔 타일의 "24시간 비용"을 "사람 응답 대기 최장"과 "숨은 후속"으로 바꿨다. 비용은 세션 표와 트리·예산에 참고로만 남겼다.
- 다음 통합 과제로 작업공간 지도를 받았다(`docs/proposals/workspace-atlas.md`).

## 독립 적대 검토 (같은 날)
