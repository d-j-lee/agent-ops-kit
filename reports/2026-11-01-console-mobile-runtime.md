# 관제실 콘솔: 첫 실제 런타임 기록과 v13 대응 (2026-11-01)

결과는 `dashboard/console.html`(v13)과 `docs/dashboard.md` §1·§2·§7에 반영했다. 이 문서는 무엇을 근거로 어떻게 고쳤는지만 남긴다.

## 기록

콘솔 v11부터 페이지가 스스로 원장 `diag/`에 진단을 남긴다. 처음 쌓인 실제 기록은 모바일 브라우저 두 건이다 [기록됨: 원장 `diag/2026-10-30.mobile`, `diag/2026-11-01.mobile`].

| 항목 | 값 |
|---|---|
| 보기 | Android Chrome, 콘솔 v12 |
| 제공된 능력 | `mcp`, `db`, `user`, `permissions` 모두 |
| 권한 상태 | granted |
| `list_sessions` | `callTool`과 `watchTool` 모두 `blocked_by_policy`, 재시도 불가 |
| 플랫폼 문구 | "tool is not available on this connector or is blocked by your organization" |
| 결과 | 계약대로 커넥터 데이터를 거둬서 세션·인박스가 비었고, 안내는 "조직 정책이 막음"이었다 |

PC 기록은 아직 없다. 그래서 이 거부가 모바일에서만 일어나는지는 [미확인]이다.

## 판단

- 계약상 `blocked_by_policy`는 권한 거부 계열이다. 커넥터 데이터와, 그 데이터로 만든 보는 사람 전용 스냅숏은 계속 숨긴다. 보이게 하려면 플랫폼 신호를 우회해야 하므로 하지 않았다.
- 원장 `handoff/current`는 세션들이 직접 쓴 문서다. 커넥터 데이터가 아니다. 그래서 거부 상황에서도 그 안의 사람 몫(`owner: user`)과 대기 중인 결정을 "당신 차례"에 보여 준다. 모바일에서도 사람이 할 일을 볼 수 있게 된다.
- 안내 문구는 플랫폼 문구에 맞췄다. 개인 계정에서 "조직 정책"이라고만 쓰면 사람이 원인을 잘못 짚는다.

## 시험

| 확인 | 결과 |
|---|---|
| 거부 모드 | 세션 행 0, 인박스 0, 스냅숏 안내 없음. 사람 몫 3건이 높음 → 낮음 → 결정 순서로 나옴. 다른 주인의 항목과 형식이 틀린 항목은 빠짐 [확인: `tests/test_console_inbox.py` `test_policy_refusal_shows_ledger_todo_not_snapshot`] |
| 변이 | 스냅숏 표시 조건에 `denied`를 넣으면 세션 58행이 새어 나와 시험이 실패함. 주인 필터와 정렬을 지워도 실패함 [확인: 변이를 넣은 사본] |
| 시험 순서 함정 | 처음에는 스냅숏이 거부보다 먼저 도착해 누출 변이를 잡지 못했다. 실제 원장은 늦게 올 수 있으므로, 거부 모드에서는 스냅숏을 거부 뒤에 보내도록 고쳤다 |
| 화면 | 390px에서 가로 넘침 0, 페이지 오류 0 [확인: 스크린숏] |

## 미확인

- PC(데스크톱 앱·웹)에서 `list_sessions`가 동작하는지. PC에서 한 번 열면 `diag/<날짜>.app` 또는 `.browser`가 남는다.
- 모바일 거부의 원인. 그 화면에서 도구를 쓸 수 없는 것인지, 정책 때문인지 플랫폼 문구로 구별되지 않는다.
