# 독립 검증 라운드 기록 — Rust 작업 하네스와 검증 플레이북 (2026-10-28~30)

> **이력 기록.** 규범 문서가 아니다. 한 세션에서 같은 산출물에 검증 방식을 바꿔 가며 붙인 결과다. ⑦ 회귀 고정(`docs/patterns/regression.md`)과 ⑧ 작업 레포 하네스(D20) 제안의 근거다. 수치는 각 검증 서브에이전트의 보고서에 적힌 건수 [기록됨]와, 이 세션의 작업 완료 알림에 찍힌 시간·토큰 [확인]이다. 보고서 원문은 발췌하지 않는다(공개 레포 규칙).

## 1. 대상

| 산출물 | 내용 |
|---|---|
| Rust 작업 하네스 | 에이전트 규칙, 단일 검증 진입점 `verify.sh`(policy·light·static·fast·full), Claude Code 훅 4개(세션 시작·프롬프트 기준점·편집 직후 검사·턴 종료 게이트), 적대적 리뷰어 서브에이전트, CI·Dependabot·cargo-deny, 예제 크레이트와 PyO3 브리지 |
| 검증 플레이북 | 교차·적대·회귀 검증의 차이, AI에서 달라지는 점(연구 근거), 라운드 설계, 브리핑 템플릿 |
| 공개 레포 핫스팟 | `reports/2026-10-30-hotspots.md` |

## 2. 라운드

| 단계 | 검증자 | 방식 | 찾은 것 | 시간 · 토큰 |
|---|---|---|---|---|
| 0 자기 검증 | 작성자 | 전체 게이트, 훅 시나리오 7개, shellcheck | "전달 가능"으로 판단 | — |
| 1 적대적 | 새 서브에이전트. 코드와 공격 범위만 받음(작성자 결론 없음) | 레포 사본에서 공격 실험 | 높음 4 · 중간 10 · 낮음 14 | 115.6분 · 195,845 |
| 2 회귀 재검증 | 1과 같은 서브에이전트(발견 목록 보유) | 발견마다 같은 실험을 다시 + 수정이 만든 회귀 탐색 | 높음·중간 중 FIXED 9 · PARTIAL 4. 새 문제 중간 2 · 낮음 2. 공허한 테스트 3 | 54.4분 · 261,878 |
| 3 적대적 | 새 서브에이전트. 앞 라운드 발견 목록은 받지 않음 | 최신 변경에 집중, 시간 제한 요청 | 높음 0 · 중간 3 · 낮음 5 · 문서 6. 공허한 테스트 1개 더 | 176.6분 · 206,517 |
| 팩트체크 | 새 서브에이전트 | 가이드의 주장을 출처와 대조, 과장 탐지 | 높음 3 · 중간 7 | 53.1분 · 219,749 |
| 4 적대적 | 새 서브에이전트 | 플레이북 + 핫스팟 결과물 | 높음 0 · 중간 6 · 낮음 다수 | 약 33분 |
| 5 회귀 재검증 | 4와 같은 서브에이전트 | 수정 확인 | 중간 6 모두 FIXED. 새 높음·중간 0. 낮음 8 → 모두 고침 | 약 10분 |

시간·토큰은 작업 완료 알림 기준이다. 토큰은 알림에 표시된 값이고, 누적 사용량인지 마지막 맥락 크기인지는 [미확인]이다. 4·5의 시간은 서브에이전트 기록의 첫·마지막 시각 차이다 [확인].

## 3. 관찰

| 관찰 | 내용 | 등급 |
|---|---|---|
| 자기 검증은 "완료"라고 했다 | 게이트와 시나리오 테스트를 통과한 뒤에도 분리된 적대적 검증이 높음 4건을 찾았다. 네 건 모두 작성자가 미리 적어 둔 시나리오 목록에 없던 경로였다 | [기록됨] |
| 수정은 회귀를 만든다 | 2라운드와 3라운드 모두 직전 수정이 만든 회귀를 찾았다(예: 2라운드 수정 뒤 빈 저장소의 첫 커밋으로 게이트가 우회됨) | [기록됨] |
| 회귀 테스트도 검증해야 한다 | 수정마다 만든 회귀 테스트 중 4개가 보호 장치를 지워도 통과했다 | [기록됨] |
| 검증 환경도 속인다 | 테스트용 사본과 원본이 빌드 디렉터리를 공유하자 원본 검증이 사본에서 빌드된 산출물과 경고를 재사용했다. 2라운드에서 거짓 실패가 재현됐다 | [기록됨] |
| 같은 검증자와 새 검증자는 역할이 다르다 | 같은 검증자는 발견 목록을 들고 있어 수정 확인이 빨랐다. 새 검증자는 앞 라운드가 보지 못한 회귀를 찾았다 | [기록됨], 해석은 [추론] |
| 새로 찾은 높음은 빠르게 줄었다 | 새 발견 높음 4 → 0 → 0, 중간 10 → 2 → 3. 2라운드에는 부분 수정 4건(높음 1 · 중간 3)이 남아 있었다 | [기록됨] |
| 시간 제한은 프롬프트로 지켜지지 않는다 | 3라운드에 "한 시간 안쪽"을 요청했으나 176.6분이 걸렸다 | [확인] |
| 공격하라고 하면 실제로 공격한다 | 1라운드 검증자는 자동 허용 규칙에 걸리는 형태의 명령으로 임의 명령을 실행할 수 있음을 보였다. 검증자는 비밀값과 푸시 권한이 없는 사본에서 돌려야 한다 | [기록됨] |
| 멈춤 기준을 다 지키지 못했다 | 3라운드의 중간 3건은 고친 뒤 실패 → 통과 테스트로 확인했지만 새 검증 라운드는 돌리지 않았다. 5라운드 뒤에도 새 검증자 라운드는 돌리지 않았다. ④의 종료 조건으로 보면 사람이 남은 위험을 받아들일지 정해야 하는 경우다 | [확인] |
