# 관제실 콘솔 v11: 실제 런타임 대응 기록 (2026-10-30)

결과는 `dashboard/console.html`과 `docs/dashboard.md` §2·§5에 반영했다. 이 문서는 무엇을 근거로 어떻게 고쳤는지만 남긴다.

## 계기

사용자 보고: "아티팩트가 제대로 동작하지 않는다. 실사용은 PC지만 클라우드에서도 되게."
허브는 실제 claude.ai 화면을 볼 수 없다. 그래서 두 가지로 접근했다. 하나는 플랫폼 계약(런타임 0.2.87의 타입 정의)과 코드를 대조하는 것이고, 다른 하나는 페이지가 스스로 진단을 원장에 남기게 하는 것이다.

## 계약 대조로 찾은 원인 후보 [문서: mcp.d.ts·permissions.d.ts]

| 후보 | 근거 | 조치 |
|---|---|---|
| 첫 연결이 `watchTool`뿐이었다. watch는 동의를 묻지 않고 `approval_required`만 받는다. 옛 런타임은 이 코드를 `upstream_error`로 바꿔 보내서 허용 버튼조차 뜨지 않을 수 있었다 | mcp.d.ts 232–243 | 권한 상태 확인 → 시작 때 한 번 `request` → `callTool` 1회 → watch |
| 내장 `permissions`를 쓰지 않아 거부 상태에서 빠져나갈 길이 없었다 | permissions.d.ts | `manage()`로 권한 패널 열기 |
| 권한 선언에 `get_session`을 추가해 동의 범위가 바뀌었을 수 있다 | [추론] | 위 흐름이 다시 묻는다 |
| 커넥터 없는 보기(모바일 앱 등)에서 빈 화면이었다 | claude.d.ts | 보는 사람 전용 스냅숏 |
| 좁은 화면에서 인박스 본문이 한 글자 폭으로 눌렸다 | [확인: 390px 스크린숏] | 버튼을 본문 아래로, 표 열 줄이기 |

## 독립 적대 검토 (계약 대조)

새 서브에이전트가 계약 문서와 v11 초안을 대조했다(270k 토큰, 15.7분 [확인: 작업 완료 알림]). 치명 1, 높음 2, 중간 6, 낮음 7건이 나왔다. 1–4번은 검토자가 모의 런타임으로 재현했고, 허브는 시나리오 시험으로 수정을 확인했다.

| 지적 | 조치 | 확인 |
|---|---|---|
| 치명: 첫 조회가 일시 오류로 두 번 실패하면 watch가 시작되지 않아 "불러오는 중"에 영구 정지 | 첫 조회의 성패와 상관없이 watch 시작 | 시나리오 H: 12건 복구 |
| 높음: 시작 때 동의를 최대 3번 물음. 요청이 대기 중이면 버튼이 먹통 | 요청 결과가 `prompt`이면 멈추고 버튼만. 버튼은 `callTool` 1회. 무인 재시도는 `granted`일 때만 | 시나리오 A·B·I |
| 높음: 스냅숏이 권한 철회를 우회. 편집자끼리 목록이 섞임 | 권한 거부·정책 차단 때는 스냅숏을 보이지 않음. 경로를 `data/users/<id>/snapshot`으로 | 시나리오 J(정책 차단 → 0건), K(커넥터 없음 → 12건) |
| 중간: 일시 오류 때 `get_session` 반복 호출 | 그 회차를 멈추고 `retryAfterMs` 또는 30–60초 뒤 재개 | 코드 |
| 중간: 크기 검사가 UTF-16 길이 기준 | UTF-8 바이트로 재고, 실패하면 줄여서 1회 재시도 | 코드 |
| 중간: 좁은 화면에서 세션 표 열이 눌림 | 760px 이하 3열만 | 스크린숏 390·480·1280px, 가로 넘침 0 |
| 중간: 보강되지 않은 값으로 원장 등록을 덮어씀 | 비용 null이면 기존 값 유지, 보관 상태 보존, 스냅숏 보기에서 차단 | 코드 |
| 중간: 포인터를 놓치면 화면 갱신이 멈춤 | 1.5초 상한, blur·visibilitychange에서도 해제 | 코드 |
| 중간: 원장 구독이 끊기면 그대로 굳음 | `unavailable`이면 다시 구독, `revoked`이면 비우고 안내 | 코드 |
| 낮음 7건 | UA 판별 순서, `u.can` 없는 경우, 알 수 없는 응답 형식, `user_changed`, watch 등록 실패, 비편집자 안내 문구 | 일부 반영. 일괄 보관 때 감사 문서의 마지막 쓰기 우선 문제는 남김 |

시나리오 11개(동의 흐름 6, 스냅숏 정책 2, 화면 폭 3)를 모의 런타임에서 모두 통과했다. 레포 시험은 `tests/test_console_inbox.py`(스냅숏 대체 포함) 4개를 포함해 54개 통과다.

## 두 세션 통합

같은 날 시작한 다른 세션이 사용자의 다른 레포(비공개)에 환경 기반을 만들었다. 시간대·로캘, Setup script, `env-check` 훅, "변경 경계" 메모가 그것이다.
- **V1 첫 실사용:** 그 세션의 "PR 준비 완료, CI 통과" 주장을 GitHub 원천과 대조했다. head sha 일치, CI 3종 성공, 병합 가능을 확인했고, draft라서 사람의 Ready for review가 남았다. 원장 `verifications`에 기록했고, 콘솔 인박스에 배지로 보인다.
- **환경 미적용:** 같은 환경을 쓰는 이 세션의 새 컨테이너에서 `TZ`·`LANG`이 비어 있었다 [확인]. 환경 설정에 붙여 넣는 일이 사용자에게 남아 있다.
- **역할 분담:** 환경 기반은 그 레포가 맡고, 협업 관리 계층은 이 키트가 맡는다. README "이어받기"에 적었다.
